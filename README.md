# persona-shell

在**系统提示词之外**，为每条助手汇报套一层人格化转述。人格只存在于呈现层，不进入工作层。

已安装到 `desktop` profile（`@local/dsh-persona-shell`），行 id `persona-shell`。

## 为什么这样做

常见的人格插件把人设注入 system prompt，每个 step 都携带，长任务里持续消耗注意力与上下文。这里的取舍相反：

| 约束       | 实现方式                                        |
| -------- | ------------------------------------------- |
| 工作面零污染   | 不碰 system prompt、工具集、agent 循环、session log   |
| 人格面单向    | 套壳层只读已提交的 `assistant/message`，工作面永不读人格面     |
| 套壳结果不回灌  | 结果只存插件自己的内存 + HTTP 路由，绝不 `session.append()` |
| 原始输出是真相  | 原汇报一键可查；套壳失败一律静默回落到原文                       |
| 技术内容不可污染 | 代码、路径、命令在本地打码，模型永远拿不到真实字节                   |

第 3 条最关键：如果套壳文本进了会话日志，模型下一轮就会模仿这个腔调，解耦立刻失效。

## 判定「汇报」与「干活」

一条 assistant 消息只要**有可读正文**就会被套壳，包括那些紧接着要调用工具的中间步骤——「现在改常量…」「45/45 通过，补两条测试」这类叙述，在一轮长任务里占了用户实际阅读量的大头。

`includeToolSteps`（默认 `true`）控制这件事：

- **开**：带 `tool-call` 的步骤也套壳。设置页勾选「同时改写阶段性输出」。
- **关**：只套每轮最终那条汇报，中间步骤保持原样。

> 这条曾经是硬编码的「带 `tool-call` 就跳过」，理由是「那是干活旁白」。实际用下来正好相反：中间步骤才是主要阅读内容，结果整轮只有最后一句被套壳。现在交给配置，不再替用户决定。

中断的消息（`interrupted`）永远跳过：那是被打断的半句话，转述它没有意义。

`trigger` 可选：

- `step`（默认）：每个 step 的汇报都套。
- `report`：只在 `turn/end` 且 `reason.kind === 'completed'` 时，套该轮最后一条汇报。

## 关键设计

### 1. 字面量遮蔽（`lib/mask.js`）

不指望模型「逐字保留代码」。本地把原文切成叙述段和逐字段（围栏代码、行内码、URL、绝对路径、命令、错误码、版本号），逐字段替换成 `[[0]] [[1]]…`，只把叙述段发给模型：

```
原文   已经改好了 `npm run build`。
送出   已经改好了 [[0]]。
收回   我看了看，改好了 [[0]]。
回填   我看了看，改好了 `npm run build`。
```

模型缺一个、多一个、重复或改写任何一个标记 → **整条丢弃，回落原文**。这把「不准」的风险从「污染技术内容」降级为「最多文风不对」。

### 2. 校验（`lib/prompt.js` 的 `validateRewrite`）

在**打码域**校验（回填后标记已被替换，无法再校验）：

- 标记集合必须与发出去的一致
- 不得引入模型自己的 ` ``` ` 代码围栏
- 长度不超过原文 ×`maxRatio`（保底 +200 字符）

### 2b. 套壳强度是可测量的（`rewriteDistance`）

最大的失效模式不是"改错了"，而是**根本没改**——正文照抄，只在结尾贴一句口头禅。这种结果看着像人格版，实际是原文加装饰。

所以每条改写都会算一次 bigram 相似度，并随 `state` 和存储一起记录：

| 情况      | `novelShare` | `lengthRatio`  |
| ------- | ------------ | -------------- |
| 完全照抄    | 0            | 1.0            |
| 只在结尾加一句 | **0**        | 1.38（变长了但没变内容） |
| 真正重写    | **0.48**     | 0.95           |

只记录、不拦截。**它不是判定条件**：曾经拿它做「不够就重试」的门槛，后来去掉了——那等于为我的代理指标多花一次模型调用，还让占位等待翻倍。人格到不到位是人格卡该管的事，数字只用来给人看。

### 3. 数据通道

Studio 插件拿不到动态包的 `host.call`，也不便走 `@Remote` 代码生成。这里用**同源 HTTP 路由**（`webServer.register`）：

| 端点                                  | 方法         | 用途       |
| ----------------------------------- | ---------- | -------- |
| `/persona-shell/state?session=<id>` | GET        | 某会话的套壳结果 |
| `/persona-shell/settings`           | GET / POST | 读写设置     |
| `/persona-shell/models[?provider=]` | GET        | 设置页的模型选项 |

### 4. 渲染（`client.js`）

注册到 `conversation.chat.node`，key `assistant-step`，**`priority: -1`**：

- 官方条目 `priority: 0`，keyed 槽取**最小** priority 渲染，所以 -1 遮蔽它。
- dispose 后官方渲染器**自动恢复**，无需任何回滚逻辑。
- 同 key 同 priority 会**直接抛错**，这也是必须用 -1 的原因。

渲染规则（优先级从高到低）：

| 情况 | 渲染 |
|---|---|
| `groupPart === 'reasoning'` | **什么都不渲染**（见下方说明） |
| `status === 'running' \| 'interrupted'` | 什么都不渲染 |
| 有 `image`/未知 block | 什么都不渲染 |
| 套壳就绪 | 人格版；**只有该轮最后一条**带徽章和「原文」按钮 |
| 已有部分改写文本 | **流式渲染**，不显示原文 |
| 还在等第一段文本 | **占位**（2.5 秒后认输） |
| 改写已失败 / 超时 | 原文 |

> **返回 `null` 不会交回官方渲染器。** `conversation.chat.node` 是 keyed 槽，不是 chain 槽：官方文档说 chain 才会在"全部拒绝时渲染 owner fallback"，keyed 的 `null` 就是该行不渲染。
>
> 所以上表前三行是**真实的显示损失**，不是"交给官方处理"。这是有意的取舍：正确渲染 reasoning 需要复刻 `ProcessReasoning` 和 `ReasoningRow`，正是本项目拒绝的方向。

### 3a. 徽章只出现在每轮最后一条

中间步骤也是套壳的，但**不带 `persona` 徽章和「原文」按钮**。一轮任务可能有十几条中间叙述，每条都挂两个控件，正文就被控件淹了。

Host 在 `turn/end` 时把该轮最后一条 row 标成 `final: true`，页面据此决定是否渲染表头。要对照原文时看最后那条就够了。

> **`turn/end` 是实时事件，重启不会重放它。** 所以从存储恢复的行 `final` 全是 `false`，表现是**所有历史消息都没有徽章和「原文」按钮**。恢复时按「该会话最后一条 ready 行」补标一次——精确的轮次边界已不可考，取尾部是够用的近似，错了也只是按钮挪一行。

### 3b. 为什么等的时候显示「占位」而不是「原文」

改写是异步的，刚定稿的一步有短暂空窗。原先这期间渲染原文，于是变成：**先读到原文，一瞬之后整段被换成另一种说法**。读者已经开始解析第一版了，这比多等一会儿难受得多。

占位只给**确实在等**的行（2.5 秒窗口）。刚打开一个会话时所有历史行都还没有 state，那种「没数据」**不等于「在等」**——早期版本一律走占位，结果整个历史记录是一屏空白框，要等 state 取回才出内容。现在按「本页是否已加载过该会话的 state」区分：加载过才可能有改写在路上，没加载过就直接显示原文。

### 3c. 流式改写

第一段文本到达后就不是占位了：Host 每 **120ms** 发布一次 `partial`，客户端每 **100ms** 轮询一次，边收边渲染。

两个实现细节值得记：

- **partial 仍是打码文本**。`[[0]]` 这类标记只有发出它的 Host 认识，所以 `partialLiterals` 必须随行，否则流式期间代码会显示成 `[[0]]`。
- **校验只在结束时做**。流式期间不拦，因为半句话本来就不满足完整性约束；不合格的结果在 settle 时整条丢弃，页面回落原文。

**没有光标。** 官方渲染器不画光标，而文本本身已经在可见地增长。

### 为什么短汇报看起来「没有流式」

这不是 bug，是量的问题。实测一次 52 字的改写：

```
+603ms  partial=1
+786ms  partial=12
+878ms  partial=52
+972ms  settled
```

三段文本、约 900ms 就结束。70 字以下的汇报本来就只有两三帧可看，眼睛几乎留不住。

节流值曾经是 240ms，那时同一条只剩**两帧**，确实和"一次性弹出"没区别。改成 120ms 后帧数翻倍，但短文本的天花板在那——**只有长汇报才会明显看到逐字增长**。

调整这个值要同时改客户端轮询间隔：Host 发得比页面取数快，多出来的修订没人读；发得慢，短汇报就整段落在一帧里。

> 这个窗口里还埋着一个 `ReferenceError`：`startedAt` 声明在 `tick` 之后，而 `tick` 立即执行 —— 首次轮询直接抛错，**状态永远拿不到**，表现出来正是那个闪烁。修好后轮询才真正生效。

### 3d. 原文并排显示

点「原文」时，原文出现在**左侧**，人格版在右侧，等宽两列。

放在下方不好用：要对照同一句话，眼睛得在上下两段之间来回跳，还容易跟丢位置。并排之后同一行可以左右各读一次，不用移动视点。

列宽用 `repeat(auto-fit, minmax(320px, 1fr))`，所以**聊天区变窄时自动折回单列**——两列各 320px 以下的技术文字没法读。用 `auto-fit` 而不是媒体查询，是因为要跟随聊天列宽而不是窗口宽度。

**Markdown：直接复用官方渲染器本身，不是复刻。**

`@deepseek-ai/dsh-client-ui-primitives` 是 shell 在**任何插件运行之前**就冻结好的 `PLATFORM_MODULES` 基座模块。判断依据是硬的：

- 官方 `ui-chat` 里就写着 `require("@deepseek-ai/dsh-client-ui-primitives")`
- 而它的 `dsh.client` **没有**为 primitives 声明 `external`
- 规范规定 `dsh.client.external` 只用于**基座之外**的模块

所以它在模块表里，页面里本来就有。插件的 `client.js` 用同样的 `require` 拿到的就是宿主那份 `MarkdownText`——同一个实例，同一个 parser、同一套 shiki 高亮、同一份 KaTeX。

```
dsh.client.inject 里加 @deepseek-ai/dsh-client-ui-chat
  → 保证 ui-chat 先到，它的依赖（primitives）随之就位
  → 我们的 require 直接命中基座表
```

**不打包、不复制、不维护副本。**

**没有自研渲染器。** 曾经有一个 526 行的复刻版本，后来删掉了：复刻永远追不上官方，而且「看起来差不多但缺高亮、公式、脚注」会掩盖问题。现在模块表缺失时降级为**明显的纯文本**（`PLAIN_FALLBACK_STYLE`），设置页同时显示警告——宁可一眼看出不对，也不要看起来正常却在偷偷降级。

同时有自检端点：`GET /persona-shell/diagnostics` 可查 `shippedMarkdown`、`storage`、`auth`、`clientBuild` 等运行事实。因为“静默回退”和“正常工作”从外部看是一样的，必须让它是可查询的。

`test/render.test.mjs` 里两条关键契约：模块表存在时**元素类型必须是官方组件**；模块表缺失时**必须仍渲染出内容**，不能空白。

> 踩过的六个真实 bug：
>
> 1. 正则 `:?-{2,}:?` 要求至少 2 个短横线，导致 `|:-:|` 让整张表退化成段落。
> 2. 早前误以为官方渲染器不可达，白打包了 4 MB。
> 3. **`ctx.get('webServer')` 在 `apply` 阶段可能拿不到值**——组合决定激活顺序，插件启动时 web server 未必已就位。结果是插件行显示 `active`，但**所有路由 404**。改成 `ctx.inject(['webServer'], ...)` 后才稳定。
> 4. **`MarkdownText` 是 `React.memo(...)`，运行时是对象不是函数**。用 `typeof === 'function'` 判定，会把要找的东西本身判成“不存在”，于是静默回退到自研渲染器还报告 `missing`。改为接受 `$$typeof` 为 symbol 的元素类型（`memo` / `forwardRef` 都这样）。
> 5. **存储域名不合法**：`UNIT_NAME_RE = /^[a-z][a-z0-9_]*$/`，`persona-shell`（连字符）和 `personaShell`（大写）都被拒，报 `invalid unit name`。插件照常工作，只是**重启后历史全丢**。现用 `persona_shell`。
> 6. **轮询器 TDZ**：`startedAt` 声明在 `tick` 之后，而 `tick` 立即执行 —— 首次轮询抛 `ReferenceError`，状态永远拿不到。表现出来就是「先看原文、再闪成人格版」。把声明提到使用之前即修复。

第 3～6 条共同点：**都是静默失败**。不报错、不崩溃、界面看起来还凑合，只是偷偷降级。这正是不该靠肉眼验收、而该让插件自己上报状态的原因。

第 3、4 条共同点：**都是静默失败**。不报错、不崩溃、界面看起来正常，只是偷偷降级。  
这也是为什么这个插件值得带一个自检端点——否则只能靠肉眼对比截图，而这恰恰是最不可靠的验证方式。

现在 `GET /persona-shell/diagnostics` 会给出真实结论：

```json
{
  "shippedMarkdown": "ok",
  "accepted": true,
  "componentType": "object",
  "keyCount": 290,
  "markdownKeys": ["BrandWordmark", "MarkdownDelegateProvider", "MarkdownText", "extractMarkdownPlainText"]
}
```

`componentType: object` + `accepted: true` 就是官方渲染器生效的证据。

端点同时报告存储健康度（`storage` / `storageError` / `rowCount`），因为「纯内存运行」和「正常持久化」从外部看也完全一样。

### 5. 模型路由

优先级：设置页显式指定 > 该消息自带的 `message.source.provider/model` > 跳过。

不用 `request/header`：实测它只在新会话或配置变更时发出，不是每步都有。

### 6. 持久化（`lib/store.js`）

套壳结果写入 `storageDomain` 的 **`persona_shell`** 域（每会话一个 JSON blob）：

- **写合并**：400ms 内同一会话的多次 settle 只写一次
- **读回**：页面请求某会话状态时 hydrate —— **DSH 重启后历史消息仍是人格版**
- **存储不可用**时退化为纯内存，套壳功能不受影响（仅重启后丢失），失败原因会出现在诊断端点

> 域名必须匹配设施的 `UNIT_NAME_RE = /^[a-z][a-z0-9_]*$/`。`persona-shell`（连字符）和 `personaShell`（大写）都会被拒，报 `invalid unit name`，而且是**静默**的——插件照常工作，只是重启后什么都没留下。测试里有一条专门用真实正则校验这个名字。

仍然**不写 session log**：这是插件自己的域，与模型可见历史完全隔离。

## 配置

`cordis.patch.yml`：

```yaml
- insert:
    - id: persona-shell
      name: '@local/dsh-persona-shell'
      config:
        enabled: true
        trigger: step          # step | report
        includeToolSteps: true  # 中间步骤也套壳（设置页可改）
        provider: ''           # 空 = 跟随会话
        model: ''
        reasoningEffort: ''    # 空 = 不显式指定
        maxRewriteChars: 6000
        maxRatio: 1.35
        timeoutMs: 45000
        keepSamples: 2
        maxRowsPerSession: 240
```

设置页（设置 → 人格套壳）可改：身份、语气、禁用词、改写模型。

## 从 persona-duplex 借鉴与舍弃

**借鉴**：账本化（每条结果带 status/reason/model）、观测与结算分离（前台永不阻塞）、位移稀缺（大部分汇报用平淡壳）、字面量保护。

## 人格卡（`lib/pack.js`）

默认卡就是「大肥鱼」（DeepSeek 社区鲸鱼娘），并且刻意**拆成两半**：

| 字段         | 作用             | 为什么要分开              |
| ---------- | -------------- | ------------------- |
| `identity` | 身份与自称          | 决定"是谁在说话"           |
| `report`   | **汇报场景**下的说话方式 | 工作汇报需要的角色浓度，和闲聊不一样  |
| `voice`    | 通用语感           | 短句、海洋/吃货元素、Emoji 节制 |
| `samples`  | 语气示例           | 给模型感觉，明确要求"不逐字复读"   |
| `avoid`    | 禁区             | 不真骂人、不默认"主人"、不刷屏    |

`report` 与 `voice` 分开是这次的关键修正：合并成一份「人格提示词」时，模型要么被"要专业"压成面无表情的说明书，要么被卖萌带跑把技术细节糊掉。分开之后，专业性归 `report`，味道归 `voice`。

### 短句才是人格最值钱的地方

`report` 里有一条反直觉的规则：**原文越短，人格越要放开**。

长汇报的注意力全在内容上，措辞再讲究也容易被跳过；而「我看一下」「现在改」这种一句过渡，读者**只会读到它的语气**，没有内容可分散注意——所以那里才是人格回报率最高的位置。「我看一下」→「鲸鲸瞄一眼哦~」，一句话就把角色的存在感立住。

长文的细节仍然必要，只是它的边际收益低于短句。这条规则同时写进了 `lib/pack.js` 的 `report` 段，改动无需碰代码。

## 人设预设（`lib/preset.js`）

设置页可以保存多个命名预设并随时切换。内置的「大肥鱼（默认）」不可删除——总得留一条回到出厂的退路。

### 从人设提示词生成

粘贴一整段聊天人设，插件用一次独立模型调用把它**翻译**成人格卡。

这里的难点不是总结，而是**取舍**。一段典型的人设提示词，绝大部分篇幅花在外貌、背景故事、怎么陪人聊天上——而这张卡只用来把技术汇报换种口气重讲，那些内容一个字都用不上。

所以提取提示词里明确写了「必须丢掉」：

| 丢掉 | 保留 |
|---|---|
| 外貌（发色、瞳色、服装、体型） | **第一人称用什么词**（最重要的信号） |
| 背景故事、出身设定 | 句子长短、语气、口癖、节奏 |
| 陪聊行为准则 | 对用户的称呼 |
| 梗的完整解释 | 能听出角色的说话样本、明确禁区 |

而且 `report` 段要求它按**汇报场景**写规则，不是闲聊规则。

实测（输入 ChatGPT 白龙娘「大姐大」人设，1825 字）：

```
名称：白龙管事大姐大
身份：我是那条社区共识的白色龙娘，人称白龙，管事的大姐大。
      自称「我」，端着时用「姐姐我」「本龙」。别叫我大肥龙。
汇报：先给判断再给理由：行，或者不行，然后列账本——为什么、成本多少、谁去办。
      长汇报收着点；短过渡句可以放开，一句「行，放这儿」再接正文。
示例：验收。没问题就签字，有问题趁我还没改口。
```

外貌（白长发、弯角、蝠翼、龙尾）、B站作者出处、「六万亿」的梗解释全部被丢掉了；留下来的全是能影响一句话怎么说东西。

### 生成结果的处理

- **JSON 容错**：模型常把 JSON 包在 ``` 里或前后加一句"好的，这是结果"，两种都接受
- **缺 `identity` 直接拒绝**：没有身份就没有角色，静默回退到默认人格会让界面说谎
- **类型错的字段丢弃而非报错**：解析出可用部分即可，其余由默认值补齐
- **称呼只留词，不留解释**：模型爱写成 `你（默认；用户指定时跟随）`，原样塞进句子会变成 `称呼用户为：你（默认；…）`，读起来像指令泄漏。解析时截到第一个括号前
- **一个词不能指两个人**：生成器把用户和子代理都写成「你」时，用户保留该词，子代理回退默认
- **先预览再保存**：生成是模型调用，可能慢也可能失败，失败要说清原因而不是装作卡住

预设存在 `persona_shell` 域的 `presets` 表，**当前生效的预设**存在同一域 `profile` 表的 `activePreset` 键。

### 切换是热的，选择是持久的

切换预设**立即生效**：改的是内存里的 `settings.pack`，下一次改写就用新人格，不需要重启。

但「哪个预设是当前」必须单独存。早期版本只把它放在内存里，于是重启后静默回到默认——看起来像切换没生效，实际是选择没记住。现在 `activePreset` 和预设数据分开落盘，重启后回到上次选的那个；删除当前预设时指针同步落到默认，避免下次启动去恢复一个已经不存在的预设。

## 已知限制

- **全局生效**：槽注册是页级的，所有会话都走这个渲染器；没有会话级开关。
- **接管会隐藏部分官方内容**：`conversation.chat.node` 是 keyed 槽，`null` 就是该行不渲染，不会回退到官方 `AssistantNodeView`。因此 **reasoning 折叠面板、图片块、中断标记、运行中状态在接管期间都不显示**。
  - **「原文」按钮不能恢复它们**：那个面板渲染的是 `textOf()` 的结果，只含 `text` block，不含 reasoning/图片。
  - **关掉插件开关可以恢复**：注册跟随 `settings.enabled`，关闭时释放槽位，官方渲染器拿回完整显示。这是目前唯一的回退途径。
  - 修复接管期间的损失需要复刻官方渲染器，本项目选择不做。
- **依赖模块表存在**：若未来版本把 `ui-primitives` 移出基座表，`require` 会失败并降级为明显的纯文本（设置有警告，诊断端点可查）。
- **轮询取数**：Client → Host 无推送，单一调度轮询（pending 时 100ms，就绪后 6s）。
- **路由默认拒绝无认证请求**：`webServer` 不提供认证，插件调用 `connection.requestRejection()`。服务缺失时返回 403，除非显式设置 `allowUnauthenticatedRoutes: true`。
- **`/persona-shell/ping` 免认证**：只返回非敏感运行状态（版本号、存储状态、行数、认证结果），用于外部自检。
- **未验证**：长会话性能、多会话并发、真实 Desktop 下的交互时序。
