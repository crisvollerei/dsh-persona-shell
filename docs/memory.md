# 记忆与接力基础

记忆用于让表达更符合用户偏好，并保留有来源的互动记录。工作会话仍使用原始内容；记忆不会向 Agent 发指令或替它完成任务。

## 当前可用

- 明确的简短表达偏好由本地规则及时记录，支持共享、人格和会话范围。
- 设置页可以核对新记忆、更正和撤销，查看原话依据，置顶或删除已有记录。长期记忆管理不出现在聊天区。
- 默认关闭的后台整理可把有上限的用户短消息片段发送给当前转述模型，提炼候选。它增加模型用量，不阻塞前台转述。
- 汇报、过程补充、单次重说、静默播报与独立角色聊天共用表达偏好规则，每次最多选取 5 条，总内容不超过 600 字符。
- 设置页的「最近使用情况」区分准备选入、已提供和未发出，并解释其他同范围条目未选中的原因。
- 接力记录已经具备持久化、范围检查、接收与关闭接口；这些记忆交接记录不会自行切换报告人格或触发房间接话。会话选择、手动接力与聊天室调度各自按对应规则运行。

## 条目与范围

| 类型 | 用途 | 当前如何使用 |
| :--- | :--- | :--- |
| `preference` | 称呼、语言、表达长短与语气偏好 | 生效后供各发言渠道参考。 |
| `agreement` | 与某个人格约定的表达方式、昵称等 | 人格或会话内使用，不自动共享。 |
| `context` | 当前会话的情况与临时约定 | 可管理、可在共享会话交接中引用，不直接加入汇报正文。 |
| `episode` | 有依据的共同经历摘要 | 保留为后续交互基础，不直接加入汇报正文。 |

每条记录包含 ID、内容、分类键、适用范围、状态、来源片段、标签、版本、创建/更新时间和过期时间。

- `shared`：同一插件所有人格共享的表达偏好。
- `persona`：绑定稳定的预设 ID；改名不改变归属，新建或另存预设不自动继承旧角色的私有互动。
- `session`：绑定会话，可进一步限定人格；本地识别的临时纠正默认同时限定当前人格。管理界面手动选择「当前会话（角色共享）」时，明确允许同会话角色引用。

当前存储以单一 owner 为使用边界，`ownerId` 为本地所有者标记，不是多用户认证系统。管理路由沿用插件 HTTP 认证；未来接入多用户时需要增加真实身份隔离。

同范围、同分类的新偏好在确认采用后替代旧条目；本地识别到与旧偏好不同的新表达时，也先生成待确认更正。没有冲突的窄范围明确偏好仍可由本地规则及时记录。当前会话条目优先于当前人格，当前人格优先于共享偏好；同级优先考虑置顶和相关标签，再比较更新时间。显式识别的临时偏好默认保留一天，会话范围不向其他会话传播。

正文输入将记忆作为引用数据，要求只调整表达，仍以原汇报的事实、条件与风险为准。候选、已替代、已撤销、已忽略和已过期条目不参与选择；共同经历不进入正文。提示约束与字面量校验不构成完整语义证明。

汇报转述、过程转述及其可选补充、单次重说、静默播报使用同一筛选与提示规则。生效偏好在表达方面优先于人格卡的默认语感和示例；本次单独提交的措辞反馈优先于长期偏好。原文事实、条件、风险、发言归属与各渠道的长度和输出约束始终优先。静默播报也可以参考称呼与关心方式，但不会因此读取会话正文、工具参数或共同经历。各请求按自己的当前文本匹配标签，因此统一规则不意味着每次选择的条目完全相同。

## 最近使用情况

在「记忆与约定」展开 **最近使用情况**，可以按上方人格筛选或按发言渠道查看。面板默认收起，展示三个请求计数与可展开的明细；条形图仅表示选入和未选入的条目数量，不是偏好遵守率或模型效果评分。打开面板时读取一次，也可以手动刷新，不在聊天中增加提示或后台轮询。

- **准备选入**：偏好已选好，但尚未进入实际模型流调用。能力查询失败或请求在准备阶段取消时，仍保留这个区别。
- **已提供**：偏好随模型请求交给了 SDK 的实际调用入口；不证明远端已接收、模型已阅读或最终表达一定遵守。失败、取消和生成未采用的状态另行显示。
- **未选中**：列出当时同范围条目的排除原因，如等待确认、已撤销、已过期、同类偏好被更高优先级覆盖，或条数与内容预算不足。其他人格、其他会话的私人条目不会混入该次筛选说明。

一段过程转述的查询与续接，以及兼容性降级重试，都归为同一次逻辑请求，不重复增加使用次数。后台记忆整理和人格卡生成不属于角色发言，不加入表达偏好，也不计入这里。旧版结果不补造使用记录。

角色消息区的聊天回复也记录为一次单独的发言请求，可按「角色聊天」筛选。它读取当前角色允许使用的表达偏好，不自动采集闲聊作为长期记忆；本窗近期聊天属于独立上下文，清空长期记忆不会删除这些聊天记录。快捷回复参考是临时的用户话术候选，不读取保存的角色偏好，也不写记忆使用记录。边界见[角色消息区](./role-chat.md)。

全插件只保留最近 24 次尝试，另存于同一存储域的版本化记录中。记录只包含人格与会话编号、渠道、时间、条目编号与版本、排除原因及请求状态，不复制原话、偏好正文、汇报、思考过程或错误正文。设置页只解析当前仍可展示的对应版本；已更改、撤销、过期或删除的已选条目不从记录恢复内容。重启前尚未结束的请求标为结束状态未知，不推断成功。

关闭记忆后，各渠道停止读取偏好，也停止新增使用记录；已有记录保留。清空记忆同时清空使用记录，迟到结果不能重新建立旧记录。记录保存失败不影响转述，设置页会说明重启后可能丢失；这些记录不能作为模型遵守偏好的证明。

## 在设置页更正与撤销

打开 **设置 → 人格套壳 → 记忆与约定**，按「使用中 / 待确认 / 历史」查看。默认只展示当前人格、当前会话和明确共享的记录；「全部人格」是本地所有者的管理视图，不会让角色读取其他角色的私人记忆。

1. **更正**：选中旧记录，填写新内容和你这次更正的原话，点击「预览更正」。核对单同时展示旧内容、新内容、原话依据和适用范围；点击「确认更正」后才生效。新记录与旧记录建立替代关系，旧依据仍属于旧记录。
2. **撤销**：选中不再适用的记录，留下原话说明，再预览并确认。撤销只停用选中的记录，保留历史，不建立相反偏好，也不恢复同范围内已经被替代的更早偏好。撤销人格偏好后，原本独立存在的共享偏好仍可能适用。
3. **采用**：后台候选和手动新增先经过核对；如会替代其他同范围记录，核对单会列出受影响内容。确认前继续使用原记录。「放弃这次操作」不更改原记录。

更正与撤销固定绑定原记录的 ID、版本、人格、会话和过期时间，不能顺便扩大为共享或延长临时约定。需要通用偏好时，请在「手动记一条」明确选择共享范围。完整交互记录和外部任务事实不因此成为人格拥有的经历。

确认直接采用用户在设置页提交的决定，不依赖模型的置信度或额外审核模型。无法明确对应旧记录的表达，不自动猜目标；可以在这里选中具体记录再说明。界面不会向工作对话发送确认问题，也不会阻塞底层任务。

修改先在隔离副本中完成，持久化成功才更新正在使用的记忆。保存失败可重试；保存期间发生清空或其他更新则返回冲突，旧核对单不能覆盖新状态。重复确认同一已完成操作不会重复创建记录。输入草稿按人格或目标记录分别保留在当前页面内，收起面板不会丢失，页面刷新会清除尚未提交的草稿；已生成的核对单可以跨重启保留。

## 来源与后台整理

采集来自启用中的主工作会话；聊天室会使用适用的表达偏好，但不自动把聊天内容提炼为长期记忆。临时玩笑和本次表达要求不会因此自动成为全局偏好。

只观察已恢复设置、已启用的主会话中用户本人发布的消息。DSH 有时也用用户角色发送运行上下文、工具通知或模型切换提示；这些消息不计入写作统计，不排入后台整理，也不能成为「用户原话」。带来源标记的消息必须明确来自用户；旧会话没有标记时，兼容读取正文并剥离已知的宿主前言。可识别的代码、路径和引用块仍会过滤，但不能保证去除所有技术或敏感片段。

「以后叫我小橙，只限你，别设为全局」只对当前人格生效。自动整理按完整原话判断，提到“全局”或引用他人的台词都不等于授权。像「以后所有人格都叫我小禾」这样的明确要求会出现在设置页的**待确认**中；采用后，其他人格才会收到这个偏好。拿不准的表达保留在当前人格，仍可在设置页手动选择共享。

旧版本自动共享但没有可靠授权的记录不再提供给其他人格。能从原话确定归属的，会保留为该人格的待确认记录；无法确定归属的，不再使用。用户在设置页明确设置的共享范围保留。

后台默认每 5 分钟处理待整理消息，积累 8 条同会话、同人格消息时可提前启动；全插件同时最多一个整理任务，每批最多 12 条消息，最多生成 5 个候选。批次按人格与会话分组轮转，少量旧消息不会阻塞已满阈值的新组；热点组的即时整理也不会不断推迟稀疏组原有的等待期限。失败组保留原话并暂时让路，等下一次定时重试，不立即循环重试。它使用当前转述路由，模型查询和生成共用超时，要求明确正常结束。

模型必须引用本批实际消息 ID 和原话中的连续片段。定位成功后，证据保存该条来源的完整文本，不能把缩短的定位片段冒充整句原话。被过滤过的来源和旧版缺失完整性信息的来源明确标为片段，不补造原文；更正与撤销建议只接受完整来源，重复定位有歧义时拒绝。设置页新提交的说明按原样保存，标为「你在设置页的说明」，不会伪装成对话消息。

后台同一次整理可以提出新增、更正或撤销建议，不额外为每次操作增加一个裁判模型。可选更正目标仅包含本人格、本会话可用的生效偏好和约定；其他人格、其他会话、共享条目、共同经历不进入目标列表。共享记忆的更正由所有者在设置页明确操作。来源或目标不匹配会拒绝整批提交；共享新增候选还要求原话明确表达所有人格或全局共享。引用检查只能证明出处，不能证明语义理解正确，所有模型建议均等待设置页确认。

本地序号游标用于防止同一消息在重放、重启或重试时重复采集。整理提交只消费当前批次，新到消息留给下一批。确认更正、撤销、删除、清空和关闭功能会使过时任务失效，不允许迟到结果写回。更正或撤销同时移除相关待整理来源，使同范围内引用这些旧来源的未采用候选失效；用户以后重新明确提出的要求仍可建立新记录。模型自己的重复解释不会增加用户证据或置信度。

## 管理、迁移与容量

旧统计 profile 继续用于诊断；其语言比例、句长等不再直接转为表达偏好。旧版保存的语气纠正只迁移一次，作为标记了来源缺失的候选；原 profile 中重复的纠正文本随迁移移除。

关闭记忆保留已存条目，停止采集与使用，同时取消整理并丢弃待整理片段。关闭后台整理只停止模型整理，明确偏好仍可本地记录。后台整理关闭时，无明确偏好的普通消息不保留文本，只记录用于去重的序号。

清空会移除条目、原话依据、待确认项目、待整理内容、交接记录及诊断样本，界面要求再次确认；只保留不含正文的消息序号游标，防止旧事件重放后重新学回。彻底删除单条记忆会清理其关联核对单、待整理来源和同范围的重复片段，并撤销交接记录中对它的引用；其他独立条目不连带删除。只想停止使用一条记忆时，可以选择撤销。

当前上限：200 条记忆、80 条操作记录、48 条短消息来源、32 条待整理消息、500 个会话序号索引、50 条交接记录；单条记忆 240 字符，单条源消息或设置说明最多 1000 字符。操作记录满时先回收已完成或已放弃的记录，不丢弃待确认决定；没有空间则明确拒绝。缓冲超限保留较新内容，不是完整档案。条目满时优先回收非生效且未置顶的记录，无法回收则拒绝新增；交接满时先回收已关闭记录。会话索引满后停止为新会话采集，已跟踪会话仍可更新。

## 管理接口

所有接口均位于 `/persona-shell` 下，沿用现有 HTTP 认证。修改需要存储恢复完成；条目更新、删除、采纳和忽略必须携带当前 `version`，旧版本返回 `409`，避免覆盖其他操作。

| 路由 | 用途 |
| :--- | :--- |
| `GET /memory` | owner 管理视图：条目、操作记录 `operations`、使用情况 `usage`、当前人格、会话提示与整理状态。 |
| `POST /memory` | 新界面使用 `propose-add / propose / confirm / dismiss / pin / delete / reject`；`consolidate` 安排后台整理。 |
| `GET /memory/handoffs?session=...&persona=...` | 查询指定接收角色、指定会话的交接记录及当前仍可共享的引用。 |
| `POST /memory/handoffs` | `create / accept / close`，创建、接收、关闭交接。 |
| `POST /feedback` | 聊天页仅提供单次重说；长期记忆统一在设置页管理。旧客户端的限定范围偏好写入仍保持兼容。见[会话人格与手动接力](./conversations.md)。 |

`propose` 携带 `operation: revise / retract / accept`、目标 `id / version`；更正还提供 `content`，更正和撤销提供 `statement` 原话。范围由目标记录决定，忽略调用方试图更换人格、会话或范围的字段。`propose-add` 提供 `entry` 并生成采用核对单。`confirm / dismiss` 使用操作记录自身的 `id / version`，不是目标条目的版本。确认时再次检查目标、范围、有效期和会被替代的记录是否与预览一致。旧 `add / update / accept` 接口为历史客户端保留，新设置页不使用它们绕过确认。

### 为多个人设接力预留的规则

交接记录包含 `fromPersonaId / toPersonaId / sessionId / summary / memoryIds / status / version`。摘要当前由 owner 明确提交，来源标为 `owner-authored`，不声称是角色亲历或已经执行的工作。

`memoryIds` 只能引用生效的共享偏好，或明确向角色共享的同会话记忆。人格私有记忆、其他会话记录不能自动导出；读取交接时再次检查范围，避免创建后改成私有的条目仍被另一角色读到。接收者可以读取摘要，但不会把摘要自动复制成自己的长期经历。

状态为 `pending → accepted → closed`；接收操作对同一记录重复调用保持幂等，关闭需匹配当前版本。接收和关闭都绑定接收角色与会话。新增或关闭记录不会切换当前人格、启动模型或向工作线程发消息。

这套接口提供记忆层的交接归档。聊天顶部的手动接力使用独立的会话控制记录：先保存等待状态，再从下一份符合范围的原始汇报启用目标人格，不自动读取归档摘要或复制私人记忆。真实多用户授权、自动主持权与多人格协同另行设计。
