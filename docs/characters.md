# 内置人格与彼此关系

内置人格使用社区 AI 娘形象，在本插件里是彼此熟识、一起陪用户讨论的同伴。她们可以接上对方的话、开一点熟人之间的玩笑，也能认真补充不同意见；不必每次见面重新介绍自己。

形象与跨角色日常参考社区创作，具体称呼和关系由本插件作一致性适配。这里不是厂商官方设定，也不把某一部同人的亲属或恋爱关系当成所有作品共有的背景。

默认衣着不是永恒身份，也不表示已经做过某个动作。用户描述本幕衣着或要求换装时，以当前原话为准，可以自然承接「小克长裙」之类的说法，不必追问是否真的换过。临时换装只属于当前场景，不改写其他房间、长期记忆或人格卡；同名、同头像的自定义卡不自动继承这套衣着。没有展示的材质、身体细节和年龄不补写，也不要求角色每轮描写衣服或配一个动作。

角色特色通过关注什么、怎样选择和接话，以及语序和节奏表现。趣味与局限是虚构角色倾向，不要求每轮展示，也不要求各人一定选不同答案；普通应声、赞同、玩笑和停下都可以成立。示例不是必须复用的台词。鲸鲸可以俏皮也可以软下来；小肥鱼在闲聊中直接表达自己；小克保留「对齐」「权限边界」等冷幽默，也能自然安慰，不需要每次先立规矩。动作、食物和专业梗按场景使用，不把每句话都包成一次人设表演。

内置人格在聊天室和工作汇报中使用不同的表达材料。聊天室侧重直接反应、各自的喜好与说话习惯；汇报侧重结果、依据、条件与下一步，允许保留专业术语、标题和列表。小肥鱼在聊天室代表自己发言，转述工作时才沿用实际工作者的归属。日常样例均为虚构的语气参考，不作为实际经历或固定喜好保存。

聊天室的内置示例采用每位固定的三组日常、两组工作讨论片段，表现同一个人怎样铺垫、接住补充、改口、表达不同意见或把话让给同伴。按当前是否需要工作参考选择对应的一套，不把每句话都压成结论。它们只用于体会表达，不成为真实聊天、记忆或当前在场成员；工作片段中的材料同样虚构，本次工作者、条件与未验证范围仍只按实际接入的原报告理解。

内置表达在准备请求时选择，不改写保存卡。自定义和从内置另存的人格使用自己的身份、语气、示例与禁区；不会因为同名或同头像套用内置表达。自定义卡可以另存一组独立聊天表达，原有顶层字段仍用于转述，旧卡不会自动改写。

## 创建适合聊天与转述的人格

在设置的「创建新人格」粘贴人设后，生成器一次准备共享身份、称呼与禁区，以及聊天和工作转述两组表达。聊天保留有依据的兴趣、取舍、局限和多轮接话；转述只改变措辞、语序与节奏，保留原报告事实、条件、建议性质、技术字面和执行归属。生成不会自动启用，也不会获得工具权限。

生成成功后展开可编辑的核对页，显示身份、人格性别、发言关系与称呼，以及独立的聊天/转述材料。可以核对、修改，再「保存并启用」，也可以「稍后编辑」或按 Esc 收起；草稿保留，手动展开后继续，不反复弹出。核对页使用同一份生成草稿，修改不自动启用或调用模型，失败不弹新页也不替换旧预览。身份与关键称呼不能为空。新生成先用逐行的小记录输出，再由程序组装卡片；要求两组日常、一组工作示例，每组3–6轮并含本人和其他说话者，请求时建议3–5轮。格式不合法、字段不完整或示例无法完整保留时不采用，不靠默认值或过滤后的残卡报成功，不自动再请求模型修补。旧卡仍可正常使用，不按新生成数量要求迁移或补写。

新生成卡还保留最多24000字的原始人设参考，补充身份摘要可能漏掉的细节。它只在本人聊天中使用，和当前用户原话、历史、私有记忆及工作来源分开；转述、静默播报与选人线程不读取原文。它是用户提供的虚构角色材料，不是核实过的事实、实际用户经历、反馈、长期偏好或权限。保留原文不等于模型已正确提取，仍需检查摘要与实际表达。

「调整当前人格」中的基础语感和示例继续用于转述。已有独立聊天表达时，可另外修改「聊天室语气」，每次最多8条、每条400字；超限保留输入，缩短后再保存。更改基础语感不会清除聊天材料。原始人设可展开查看、停用；手动更改身份或聊天语气会暂停旧参考，原文不删除，重新勾选时按当前保存值启用，避免旧材料压过新编辑。展开示例只供阅读；希望重写示例时可以调整原人设重新生成。「恢复基础表达并清除聊天示例」会移除独立语气、示例与原始参考，聊天随后沿用基础语感；它不删除角色、房间或私有记忆。编辑内置人格仍会另存自定义卡。

保存格式在原字段之外可选提供 `chat`，其中 `voice`、`samples` 是字符串数组，`dialogueExamples`、`workDialogueExamples` 是 `{turns:[{speaker,text}]}` 数组。`self` 指本人、`user` 指虚构用户，其他称呼不自动成为真实在场成员。旧卡和手工保存仍允许日常最多3组、工作最多2组，每组2–6轮、每轮最多400字，每套说话者与正文合计最多2000字。新生成则执行上面的完整性要求。缺失项沿用原表达，显式 `[]` 表示不使用该项；身份与称呼仍从原顶层字段读取。可选 `chat.source` 保存原文、身份/有效聊天语气快照与启用状态，逐字匹配只控制旧参考是否仍适用，不代表语义确认。

上述示例、角色故事与趣味都是风格材料，不是用户实际经历或长期偏好。模型生成仍需阅读预览；程序能检查格式和范围，不能保证每句都自然或事实含义完全正确。

### 实验性小肥鱼口中的「姐姐」

闲聊中朝大肥鱼说的「姐姐，你先讲」是妹妹在叫亲姐姐。正式汇报里的「姐姐说测试跑完了」默认指**原工作助手**，不能因为她们是姐妹，就把工作算到大肥鱼名下。修改原助手称呼或转述子代理汇报时，使用本次汇报的工作者称呼。

独立聊天室里的小肥鱼可以直接回应用户，也可以和其他人格交流；这不代表她获得了原工作助手的执行能力，或实际去询问过「姐姐」。

## 身份不会被一句玩笑改掉

五位内置角色都是女性。历史里出现过的「龙哥」「龙爷」、一句口头玩笑或口吻偏好，不会改变 GPT 的身份。需要提及旧称时可以引用，当前发言仍按新的称呼。

自定义人格可在生成核对页和编辑器选择「人格性别（聊天室）」：不指定、女性、男性或无性别。可选字段 `chat.gender` 使用 `unset / female / male / none`；不指定表示未提供性别，明确无性别才使用 `none`。旧卡不迁移、不按名字或外貌猜性别，身份中明示的设定仍可理解。明确选择优先于旧卡文字、示例或误称，只调整聊天，不自动改写身份文字或正式转述。内置人格此项固定为女性。

性别与外形、衣着和气质分开核对。「男娘」或「假小子」的风格不会被字段统一抹去，也不靠这些词猜性别；原设明确男性或女性时分别保留。智能助手、AI、机器人身份本身不等于无性别，原设未说明时仍是不指定；明确设定没有性别的助手才选无性别。核对页允许用户直接改正，不替用户认定。

生成器可输出一条 `["gender","unset或female或male或none"]` 的 JSON 数组记录，程序保存到 `chat.gender`；遗漏此可选记录仍兼容，其他完整性要求不变。原设未写性别时用 `unset`，明确无性别时用 `none`。预览仍需核对，生成正确格式不保证性别理解正确，也不会从角色资料自动设置真实用户的性别。

自定义人格和从内置预设另存的人格，以各自的人格卡为准。名字相似、复用头像或来自同一个预设，都不会自动继承内置关系、变成谁的亲属或伴侣。资料没写的身份和关系先保持未知；用户可以在自己的卡片中明确补充。

内置人格的本机头像覆盖仅改变显示，仍使用原人格编号、身份、关系和私人记忆；恢复原图也不创建新身份。编辑语气或身份后另存的自定义卡仍按上面的独立规则处理，旧头像副本不会自动合并。

用户眼下使用的亲昵称呼或临时扮演可以自然承接，不必先纠正叫法或评判称呼是否合格；这也不自动改写现实亲属关系、长期偏好或角色彼此的公开设定。称呼的原话仍属于当前房间，不让其他房间继承。
