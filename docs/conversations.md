# 会话人格与手动接力

工作会话支持三个动作：为当前会话选人格、对一份汇报反馈、把下一份汇报交给另一人格。多人格闲聊在独立的[聊天室](./role-chat.md)中进行。

## 交互与边界

- 全局设置决定默认人格；聊天顶部可以单独选择人格，以及全部汇报或仅最终汇报。恢复默认只影响未来汇报。
- 历史汇报保留生成时的人格署名，不随当前选择变更。实验性小肥鱼明确区分转述者与实际工作者。
- 手动接力先进入等待状态，下一份符合转述范围的原始汇报到达后才接手；可以取消。新角色不读取上一角色改写后的正文。
- 每份汇报的反馈仅重写这一次；长期偏好、更正、撤销与确认都集中在插件设置的「记忆与约定」，不插入聊天页面。
- 重写失败保留旧正文；切换会话或关闭弹窗不丢弃未提交的输入。偏好只影响措辞，不能改变事实、风险和条件。

## 只重说这一份汇报

在完整工作汇报的工具栏点击 **调整表达**。可先选「短一点」「先说结论」「少些调侃」「更正式」，或填写不超过 240 字符的要求，再点击 **重新转述**。快捷选项只填写要求，不自动调用模型；本次要求不会写入长期记忆。

重述始终读取插件保存的同一份原始汇报，沿用这份汇报的署名人格，不以已经转述过的文字再改一遍。短一点只压缩重复措辞、修饰和过渡，事实、验证结果、风险与条件仍需完整；先说结论可以调整段落先后，不改变步骤关系。

此前改写失败、界面回落原文的最终汇报，只要仍有合法的原文缓存，也可以从同一入口重试。新版本通过检查后才替换当前显示，失败时保留旧正文或原文回落，以及尚未提交的要求。弹窗打开期间若汇报版本或署名改变，需要重新打开核对，不把旧输入自动提交给新目标。

缺少原文缓存的旧历史、已移除的人格、尚未完成的汇报或关闭的转述开关会显示不可用原因，不从客户端显示内容补造原文。重述不会重新执行工作任务或向原工作流追加消息。

## 数据与可靠性

会话选择和接力状态共用一个版本化记录，通过串行写入与版本校验防止旧页面覆盖新选择。选择在保存成功的瞬间按最新全局默认生效，等待保存期间的全局切换不会遗漏旧请求的取消。接力在持久化成功后生效，重复来源事件不能重复消费。存储尚未就绪时拒绝修改并允许重试。最多保存 500 个独立会话选择，满时明确拒绝新增，不静默丢弃已有选择。

接力状态为等待、已接手、已取消。已接手表示目标人格从指定来源序号开始生效；改写仍可能因模型或校验失败显示原文。一次只能安排一项等待接力，保存显式会话选择会取消等待。目标人格删除后无法接手；独立选择已删除人格的会话回到全局默认，并显示提示。

人格切换只取消受影响会话的在途转述，并清除其语气样例。更新或删除人格卡时，还会取消正在使用该卡的历史汇报重写，不打断同一会话里其他人格的请求。正文始终来自原始助手汇报；接力不控制工作代理、工具调用或任务分配。私人偏好不会因接力复制给另一人格，只有明确共享的偏好和当前会话偏好可被选择。

记录每次转述选用的偏好编号与版本，引用只解析版本未变、仍有效且仍有权限使用的条目，不用编辑后的新内容代替旧依据，也不因新的偏好排序而遗漏原先使用的有效条目。聊天页面不显示记忆管理与引用清单；记忆在插件设置页集中核对。引用不额外保存偏好正文；删除后不会从旧汇报恢复内容。旧数据只有编号而无版本时，不推断当时的内容；未记录署名的汇报显示历史人格，不推断角色。

为支持单次重说，新汇报在插件自己的结果缓存里保存原始正文，与改写结果共用每会话的行数上限；接力准备失败或取消时同样清理超量结果。不会复制思考过程、图片或工具正文。单次反馈最多 240 字符，仍经过原有打码、完成原因、长度与改写校验。记住偏好先写入存储，再启用；写入失败不影响后续提示词，保存中发生清空或其他更新时返回冲突，清空优先。

发言关系通过 `pack.narration.mode`（`voice / relay`）和 `assistant`（原助手称呼）明确描述。它约束工作归属和引语、时态的保留；这仍依赖模型遵守提示，不构成逐句语义核验，重要结论应查看原文。

## 接口

以下均沿用插件的 owner 认证，写入要求存储已就绪：

| 路由 | 内容 |
| :--- | :--- |
| `GET /conversation?session=...` | 会话选择、版本、有效人格与范围、接力状态、可选人格列表，以及 `instanceId / stateRev` 状态顺序信息。 |
| `POST /conversation` | `sessionId / revision` 加 `select / relay / cancel` 动作。旧版本返回 `409`，存储失败返回 `503`。 |
| `POST /feedback` | `sessionId / seq / version / personaId / content / scope`；范围为 `once / persona / session / shared`。过期汇报版本返回 `409`，单次重写失败返回 `422`。 |

`select` 提供 `personaId`（`null` 继承）和 `trigger`（`inherit / step / report`）；`relay` 提供 `toPersonaId`；`cancel` 提供当前 `relayId`。页面状态流同时携带 `conversation` 和每行的 `speaker / version / retrying / canRetry / memories`，不另建事件日志。

`revision` 用于保存会话选择时的冲突校验；`instanceId / stateRev` 用于界面识别 Host 重启与状态先后，防止迟到的读取覆盖新的就绪状态、默认人格或可选列表。二者不混用。

已有 `/memory/handoffs` 是记忆层的摘要与引用归档，不调度角色。当前手动接力使用上述会话记录，两者不互相隐式写入，也不把归档摘要当成新的汇报事实。

## 当前范围

当前支持显式选择与手动接力，不自动决定谁发言，不并行生成多个角色的正文，不把主助手的工作转交给另一模型。窗口草稿只在当前页面内保留，刷新页面会丢失未提交内容。原文对照与底层工作会话保持原有入口和行为。
