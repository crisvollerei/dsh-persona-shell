# 角色消息区

工作区承载正式汇报，消息区用来和角色轻松交流、探讨想法。点击「聊天室」入口打开气泡浮窗；工作区继续忠实转述，消息区使用自己的记录。

聊天室按人格本人直接交谈，不套用工作汇报的转述框架。五位内置人格分别使用聊天语气、固定的虚构日常与工作讨论样例，避免把每次接话写成汇报、建议清单或能力声明；原话归属、本人表达偏好和房间范围仍保持隔离。自定义卡保留原有内容。工作区的「口语化」开关只调整汇报句式，不改变聊天室表达。

发言提示分别准备当前人格、必要的公开原话与这次回应目标；工作资料、时间和场景说明按实际需要提供。每位内置人格固定三组日常、两组工作讨论的多轮示例，按本次是否需要工作参考选择对应的一套，不随机轮换台词。示例不进入聊天记录或长期记忆，示例中的报告与数字也不能作为本次工作依据。自定义人格仍使用自己保存的示例，生成器沿用现有格式。

## 打开与发送

- 工作会话顶部的人格控制旁直接提供 **聊天室** 按钮，不需要先在设置中启用。同一页面同时只打开一个浮窗；窗口保持到用户主动关闭。
- 首次打开没有房间时，创建一个以当前工作会话汇报人格为初始成员的聊天室。即使创建期间关窗重开，也只会有一个初始房间。此后从房间标题处切换或新建，不因为切换人格而另开历史。
- 每个房间独立保存名称、成员、回复对象、聊天与工作参考。同一个人格可以参与多个房间，各房间的记录不会自动混用。房间列表支持按名称或成员本地搜索，最近访问的房间优先，并显示「有草稿」「正在回复」；查看或搜索不会读取其他房间的工作正文，也不调用模型。
- 切换房间、关闭再打开时，按房间恢复消息锚点、相对位置与输入选区。读旧消息时不会因新回复强制跳到底部；「回到最新消息」会标出新完成的回复数量，多段气泡仍按一位角色的一次回复计数。
- 未发送草稿与阅读位置使用当前插件 profile 的独立本地命名空间保存，客户端重新打开后可恢复，最多 32 间、每间草稿 4000 字符。命名空间或浏览器存储不可用时保留页内草稿。未发送文字不会交给插件后台或模型；引用仅保存位置，恢复时重新核对本房间同范围的原话。清空或删除房间会清理对应本地状态，来源变化保留文字但去掉旧引用；迟到发送回执不能清掉另一页面新写的草稿。
- 多人格房间在输入框上方显示成员小头像与名字，支持 0～8 位有序选择。全部取消表示“发给房间”；选中多人时，第一位为主要对象，其余为次要对象。悬停可看完整名字，方向键移动焦点，空格或点击切换，不增加额外模式。
- 判断线程统一安排下一位发言者，再根据最新公共聊天准备她的请求。角色可以回应用户，也可以自然接同伴的话；不因有人先回应就让其他被叫到的人保持沉默，也不强行全员轮流表态。
- 用户没有指定对象时，全员从 0 级开始；指定时主要对象 0 级、次要对象 1 级、其他人 2 级。0 级无个人冷却，1/2 级分别等待 5/10 秒；每成功完整回复一次升一级，3 级不再参与普通判断。多个气泡算一轮，不逐气泡调用。只有用户的新发言轮刷新等级。
- 每个人格另有一次独立同伴回应机会，可回应另一位人格本周期中明确向她提出的问题或招呼。它不降低普通等级，也不会因互相点名不断增加；用过后仍要等用户新发言轮刷新。普通次数与独立机会只作为内部上限，不在台词中播报。
- 判断最高每 5 秒一次，只在公共消息或可参与成员发生变化时运行。同样的现场不会反复空调用；全部安静后等待新输入。八人房间的单个用户周期最多三十二份完整回复，不要求用满。实际发言顺序、引用与流式气泡保持一致。
- 用户可在回复期间继续发送。尚未处理的连续原话按相同对象、成员、引用与参考范围合并收取，每段仍独立显示、保留编号；改变对象或引用会另起一组。已开始的角色回复完整结束后处理新原话，原话保存失败可重试或取消。重新启动不偷偷重发输入或刷新角色额度。
- 每位发言者都知道这条消息点名了谁、现在谁还在场。用户消息只显示一个气泡，顶部以小号 `@名字` 标明当时询问的对象；各人格回复分别署名。历史中的对象与发言者不会随着之后的勾选变化而改名。
- 输入后点击发送，或按 Enter；Shift+Enter 换行，输入法选字时不会误发。回复按自然停顿形成短气泡。
- 已接入工作来源的房间，在每轮主讲前共用一次轻量参考筛选，按本条用户原话判断是否需要工作资料，并从已接入来源中选取。筛选不读取工作正文、角色卡或人格私有记忆；未打开聊天室、只切换成员或编辑输入时不调用。判断不明确或失败时不把全部工作正文作为兜底。纯闲聊不带工作片段，明确这轮不谈工作、只作开放交流或倾听时，也不额外带入旧话题与房间讨论状态；近期公开对话和用户主动引用仍保留。询问先前的非工作话题时，仍可按本房间原话接续。
- 筛选期间显示简短等待提示，不让尚未开始回应的人格显示「输入中」。消息保存完成后即可停止本轮准备，停止后不再启动排队的主讲；尚未保存的消息仍按原有发送保护处理。
- 主讲回应结束后，可以继续发送新消息。输入文字时底部恢复「发送」，新消息保存成功才结束尚未完成的接话；保存失败保留草稿和原讨论。没有输入时仍可手动停止。被新消息打断的可选接话不会留下空白错误气泡。
- 新回复支持流式显示；多人按本轮发言顺序出现，后一位的气泡不会插到前一位尚未显示的消息中间。窗口可见时，连接中断会自动重新读取已有回复，不会重复发送原消息。实际等待角色输出时，左侧显示头像与「输入中」气泡；已收到的消息只是在等下一段显示时，用省略号过渡。减少动态效果的系统偏好会改用静态省略号。文字开始后原位显示正文。重新打开时已有历史直接显示，不重新播放停顿。
- 同一次角色回复的连续气泡只在首段显示头像和姓名，后续保留对齐并缩小间距；切换发言者或进入新一轮时重新显示。分组只改变呈现，每段仍可单独引用，消息位置、流式节奏和多人发言顺序保持不变。
- 时间分隔按客户端当地日期显示：今天只显示时分，昨天显示「昨天」与时分，其余显示日期与时分。悬停可查完整日期和秒，辅助阅读也保留完整时间。同日间隔超过五分钟或跨日时显示分隔，不定时刷新界面。
- 等待较久时，显示对应当前阶段的轻量提示；悬停或展开可看本轮已用时和实际取得的调用模型，未知时不猜测。不会显示虚构进度、思考内容或内部判断日志，不因此新增模型调用；最小化或隐藏时停止界面计时更新。
- 角色气泡复用 DSH 官方 Markdown 渲染器，支持行内代码、列表、链接等排版；用户输入按原话显示。旧宿主缺少渲染器时保留纯文本，不自行解释为 HTML。
- 房间标题打开聊天室列表，标题下方直接提供「成员」和「来源 · 数量」，分别打开成员管理与参考管理；头像只作展示。输入框上方只在多人房间列出回复对象，不加分隔线或空白工具栏。底部将快捷回复、输入框展开和发送放在同一条工具栏，完整键盘提示可悬停输入框查看。
- 输入框使用斜向双箭头按钮展开或收起，保留文字、选区与焦点，不依赖右下角拖拽柄。输入框展开与聊天室放大相互独立。
- 点「最小化」将当前房间收在工作界面右下角，保留草稿。已发送的一轮仍会继续；每位角色完成一份回复，入口只增加一个未读计数，轻轻跳动提示（系统开启减少动态效果时只显示数字）。点击入口即可回到原房间。浮窗也支持放大、还原和关闭，不锁住工作页面，仍可继续操作工作会话。放大和窄屏状态都保留顶部标题栏与底部边距，短窗口下为消息和发送按钮保留空间。
- 收起和还原时，窗口与右下角入口之间使用短暂的形状过渡；打开面板和新气泡轻轻淡入，放大窗口、展开输入框也会平滑调整。动效不延迟草稿保留、参考连接释放或工作输入框交接；系统选择减少动态效果时直接切换，旧客户端不支持过渡时仍能正常操作。

打开窗口、选择角色、查看历史都不会调用模型。用户发送后，主要回应与这条消息内的有限旁听接话属于同一轮讨论；讨论结束即等待用户，不继续自动聊下去、不自动问候、不产生工作区未读提醒。未打开窗口时不轮询聊天，已有历史照常保留。

## 闲聊与关心

角色先回应用户当前的话头，再决定开玩笑、讨论或陪着听。亲昵称呼和想被照顾的表达可以直接接住，不要求用户先解释叫法；各角色仍保留自己的语气。小克可以使用「对齐」「权限边界」等冷幽默，小肥鱼则以本人身份闲聊，正式转达规则不变。

第二位主讲可以直接补自己的回应，不必先点评第一位。被叫到的人可以直接应声；没有受邀的成员则避免仅复述同伴、替她解释动作或反复评价安慰。当前没有使用旧话题、讨论状态或引用时，不向模型重复加入对应的操作说明；数据一旦使用，仍保留原来的来源与范围约束。

一次可以只接一个想法，也可以用两三句话慢慢说，留一些自然的铺垫、停顿、改口或顺带想到的话。不要求每句话都有新观点、转折和结论，也不为增加长度堆形容词或动作。个人反应、玩笑和动作不必再解释动机或自作点评；用户追问、需要澄清或工作判断需要依据时仍应说明。用户要求完整总结时，当次保留重要事实、条件与未知。

在人设和关系允许的熟人互动中，可以省掉客套、接半句话或顺口吐槽，不必反复声明分寸，也不必每条气泡都有动作和精致收尾。判断线程会先核对本轮已有回应，再给下一位一个具体小话头；普通应声和自然支线都有空间，共同问题已经问出后也可以安静等用户补充。任务方向不等于事实或操作授权，不会因此共享人格私有记忆。

括号描写默认是说话者自己的视角，动作通常省略主语，如「（坐下了）」；需要主语时沿用本人自称，角色卡或用户明确要求第三人称叙事时按要求表达。角色身份里的「她」供别人指代，不表示在自己的气泡里写第三人称旁白。动作可选，只写自己的动作和念头，不替用户或同伴安排反应，也不自动改写收到的正文。

这些是表达提示，不新增情绪识别模式、后台模型任务或自动记忆写入。临时称呼不自动成为现实亲属事实或永久关系。具体措辞仍受用户所选模型影响。

## 基础时间感知

客户端只在用户发送或重试时附带当前时区与 UTC 偏移。后台根据本轮开始时刻换算当地日期、时分和星期，供角色回答时间相关问题；同轮主讲与接话共用一份快照。重试取得新的当前时间，但不改原消息的发送时间。

有效时区优先，时区不可用时按 UTC 偏移换算；两者均不可用时明确采用 UTC，不猜测用户当地时间。只携带时间设置，不读取精确位置或附带任意提示词文字。读取和换算不增加模型调用，不建立后台报时任务。

时间快照只用于本轮角色聊天，不作为长期偏好、工作参考或正式汇报依据，也不进入房间存储或参考账本。角色不必每条消息都播报时间，不据此推断用户疲劳、在线状态或生活习惯。

## 引用消息回复

悬停消息或用键盘聚焦时，可用气泡旁的回复箭头引用这句话；触屏下直接显示入口。引用保留作者和具体气泡的位置，不改变当前勾选的 `@` 对象。输入框上方显示原话预览，长消息可点「全文」展开并独立滚动，点箭头定位原消息。按 Esc 先取消引用，再按才关闭聊天；打字、取消引用、关闭和重新打开窗口都不会丢掉本房间的文字草稿，发送失败也可继续重试。

发送后的用户气泡保留引用预览，点击箭头可定位回原消息。后台只接受消息位置，重新核对本房间已提交的原话，不采信前端传入的作者或正文。其他房间、已被重试替换的气泡、未完成的角色输出、清空前的消息和之前参考范围内的内容不能直接引用。原消息不可用时保留输入，取消引用或重新选择后再发送。

## 在设置页核对房间参考

打开 **设置 → 人格套壳 → 聊天室 → 房间参考**，按房间和某次回复查看。展开前不读取；查看时不初始化聊天室、不刷新工作来源，也不调用模型。本次运行还没打开过聊天室时，会提示先打开。

每次记录先显示「这次回应了什么」：当轮用户原话、当时的 `@` 名单，以及这位人格是第几位主讲或旁听接话。多人回答可以分别核对各自的参考；后来切换回复对象不会改写历史名单。用户原话只从该房间的确切尝试解析，不复制进参考账本；原尝试已被重试替换、聊天裁剪或参考范围改变时显示不可用，不用其他问题代替。

「本轮参考选择」显示当时是否采用工作参考、本次表达需求的初步判断，以及选择的授权来源。展开可核对判断是否来自模型、未接入来源或超时等回退。它只说明本次如何选取上下文，不代表已确认用户意图，不修改 `@` 对象、房间来源或长期偏好；这些核对信息只在设置页显示。参考筛选的调用单独计入聊天室用量。

- **工作来源**：区分当前接入的选择和某次请求实际提供的来源，保留读取时间、目标与汇报所属轮次和事件。展开时将本轮目标、本轮汇报与上轮参考分别标记；上轮汇报不能当作本轮结果，超出预算未提供的上轮参考也会说明。只有原缓存仍与当时版本相符时才展开正文，避免拿新正文冒充旧依据。
- **旧话题原话**：显示实际选入的较早聊天片段及作者，可以展开出处、暂停或恢复自动引用。暂停不删除聊天，也不妨碍用户主动引用；变更会停止本房间尚未完成的旧请求，不影响其他房间。原话超过保留范围、所属消息改变或来源范围切换后，不恢复旧内容。
- **人格偏好**：只解析该次发言人格所用的确切记忆版本。更改、删除、撤销或不再适用的条目只保留不可用提示，不从旧记录复原正文。各人格的偏好分开显示，不合并提供给别的人格。

「准备选入」不代表已经调用模型；只有请求实际发出才标记为已提供。全插件保留最近 24 次聊天请求的参考指针，跨重启保存；账本不复制提示词、消息原话或偏好正文。清空或删除房间会清理其参考使用记录。

## 房间讨论状态

在 **设置 → 人格套壳 → 聊天室 → 房间参考 → 房间讨论** 中，从本房间原话新增条目，填写整理标题并选择「讨论中、候选方案、已确定、已搁置、已否定」。这一批由用户整理，不自动提炼决定，也不为整理额外调用模型；聊天页面没有状态管理面板。

「已确定、已搁置、已否定」必须附上同房间、同参考范围的用户原话。角色方案需要方案之后的用户表达作为依据，不能用角色自我肯定或方案之前的用户提问替代确认。整理标题只是用户填写的标签，原消息保持不变，可展开核对。已确定只表示讨论中的方案获得认可，不代表工程已经执行或验证。

支持更正、移除和撤销最近 10 次修改，每次使用新版本；保存失败保留编辑内容，冲突时先刷新核对。每个房间最多 16 项，修改会停止本房间尚未完成的旧请求，不影响其他房间。清空、删除房间会清除其讨论状态与撤销记录。

后续聊天最多取得当前房间、当前参考范围内 8 项有效状态，原话及整理标题合计不超过 3000 字符。暂缓、否定的想法不会被要求反复推销，用户重新提出时仍可讨论。原话被重试替换、裁剪、清空或来源范围改变后，条目会标为不可用，不拿其他消息补位。讨论状态不写入人格长期记忆、不读取别房间内容，也不进入正式汇报或快捷回复候选的上下文。每次实际使用的条目版本和本轮职责可在参考记录中查看，更正后不从旧版本恢复正文。

## 房间与参与者

同伴们叫大肥龙「GPT」，叫 Gemini「猫猫」。大肥鱼是小肥鱼的亲姐姐；两人可以在闲聊中姐妹相称，但各自署名、各自保留记忆。小肥鱼转述正式汇报时，默认的「姐姐」指原工作助手。角色发言与旁听判断参考同一份公开设定；具体关系和出处见[内置人物关系](./characters.md)，设置页「人格」分区也可展开查看。

每位角色可以说明自己的公开身份。比如只和小肥鱼单聊，问她姐姐是谁，她仍认得大肥鱼；这不会把姐姐加入房间，也不会让妹妹看到姐姐的私聊。接话判断只参考在场成员之间的关系。自定义人格可以按公开称呼与在场角色交流，不会仅因同名、复制头像或另存预设就继承姐妹或旧识关系。

点击房间标题可以切换或新建聊天室；点击顶部明确标出的「成员」，可以修改名称、增加或移除成员。房间最多 8 位人格，头像保留圆角图标和轻微厚度，主要在角部交叠，避免遮住脸部中心：两人使用对角组合，三人使用三角组合，四人使用清晰四格；更多成员展示三张头像与准确的剩余数量。空白聊天页同比放大。成员变化或头像更新后重新组合，缺失图片使用字符头像；不重绘原图。

只保留一位成员并替换为另一人格，也会沿用同一房间的记录。新加入的角色可以阅读本房间近期公开聊天；它不会因此获得其他房间记录、其他人格卡或其他人格的私有记忆。各次请求只注入当前发言人格允许使用的表达偏好。

回复已经开始后，切换回复对象只影响下一次发送，当前回复仍属于原发言者。将正在回复的成员移出房间会停止该回复，迟到文本不能重新写回；修改人格设定或删除人格也会退休相应请求。已删除人格的历史仍按原署名显示，不能继续向它发送。

成员与名称编辑保存失败时保留草稿；版本冲突时先重新载入成员核对。清空仅删除当前房间聊天，保留成员、名称和工作参考；删除聊天室需要另行确认，不影响其他房间的在途回复、接话判断、快捷参考或长期记忆。当前存储使用房间结构，未发布的旧开发版记录不迁移。

## 参考来源与工作焦点

第一次点击才统一初始化聊天资料。选中房间后才初始化该房间的工作参考；新房间首次载入当前工作会话，以后使用该房间保存的来源，即使切换工作页或重启也不自动换成别的项目。窗口独立于工作页入口存在，切换工作会话时保留来源与草稿。窗口里的「来源」可以接入当前会话、手动选择其他项目会话或移除来源；未展开项目只读取文件夹名称。

本地操作频率决定焦点，焦点项目中已接入来源较频繁更新，其他来源低频更新。相关会话的一轮汇报结束或异常以聊天室内的元数据条目提醒，不生成额外角色发言，也不自动读取或接入关联正文。关闭、隐藏时停止资料刷新。加载层次、频率、容量与来源变更规则见[参考来源与工作焦点](./chat-context.md)。

## 角色头像

五个内置人格配有本地头像：大肥鱼、大肥龙、Claude小姐、Q 版小肥鱼和 Gemini。设置页的预设卡片与消息区使用同一张头像，不依赖外部图床。

在 **设置 → 人格套壳 → 人格** 的卡片上点击 **头像**，选择 PNG、JPG 或 WebP（不超过 8MB），预览后可调整左右位置、上下位置和缩放，再保存。处理在页面本地完成，只保存取景后的 256 × 256 PNG，图片不发送给模型。保存失败保留已选图片与取景；取消不提交。

内置人格与内置头像都保留原版。修改内置头像时会另存新人格并设为全局默认，不覆盖原版，也不自动加入聊天室或继承原人格的私人记忆。消息区已经打开时，可在成员管理中加入这位新角色。已有自定义人格可原位更换或移除头像，身份、历史与记忆不变。

没有自定义头像的人格在设置预设列表中只显示文字；消息区使用角色名的字符头像。图片加载失败时也回到字符显示。移除自定义头像不会修改角色设定。头像只作为界面资料，既不进入人格提示词，也不作为角色身份的事实依据。

角色气泡按头像主色调配色，相近颜色会略微错开，便于分辨同房成员。浅色底、细边框与姓名使用对应色系，正文保持统一的高对比度；输入状态和同一次回复的连续气泡沿用相同颜色。更换头像后自动重新取色，图片不可读时使用稳定的默认色。取色只读取界面已加载的本地头像，不增加模型调用，也不向模型发送图片。

## 我的头像与称呼

默认跟随当前 DSH 账号头像，只使用官方只读资料接口返回的图片地址。未登录、旧宿主不支持、接口失败或图片加载失败时，用户侧只显示消息气泡，不显示字符头像或空位；角色侧仍使用自己的图片或字符头像。

在消息窗口的 **设置** 或 **插件设置 → 外观** 中，可选择「跟随账号头像、使用自定义头像、不显示头像」。支持本地 PNG、JPG 和 WebP，上传后预览、调整取景，再点击 **保存我的头像**。隐藏时保留已上传的图片，方便切回；旧版已上传的头像继续作为自定义头像使用。按 Escape 先收起设置面板，不会直接关闭聊天窗口。

用户头像显示方式在本地供所有角色聊天统一使用，与人格头像、聊天和私人记忆分开保存。更换它不会创建新人格、清空聊天或影响工作汇报，也不调用模型。账号头像只在前端临时使用，不保存账号资料或远程头像地址；账号退出或变更后丢弃旧请求结果。自定义图片只保存处理后的 256 × 256 PNG，不保存原图路径和文件元数据。保存失败保留图片和取景，多页面同时修改时核对版本；旧页面不能覆盖已保存的新图，迟到的聊天快照也不能恢复旧头像或显示方式。

头像旁可以填写 **角色怎么称呼你**，最多 40 个 Unicode 字符，中文与常见 Emoji 均可；留空时不增加额外称呼要求，继续按人设自然交谈。不会从账号姓名自动填入。称呼供所有聊天室共用，点击保存后用于后续角色回复，不要求每条消息重复点名；清空只移除这项设置，不删聊天或头像。

称呼与头像使用同一份版本化用户资料，但可以分别保存。两个设置入口共用页内未保存草稿，保存失败或版本冲突时保留输入，迟到回执不能盖掉刚输入的新字。称呼只作为发言角色的文字数据提供，不改变气泡署名、引用作者、角色身份或权限，不自动写入长期记忆；正式汇报、判断线程、快捷回复参考与指令整理不接收这项资料。用户头像图片仍不发送给模型。

## 快捷回复参考

输入框上方的 **快捷回复参考** 默认不勾选。它生成的是供用户选择的话术，适合追问、澄清或整理想法。

1. 勾选选项，在输入框中写下要求，例如「帮我追问实现成本，口语一点」；也可以直接基于已有讨论生成。
2. 点击 **生成参考**，取得 1–3 条简短候选。勾选和打字本身不会调用模型。
3. 点选候选只填入输入框，用户可以修改，再点击发送。候选之间是备选关系，不会连续自动发送。

生成参考期间保留输入；编辑草稿、切换回复对象、成员或更新讨论后，旧候选失效。关闭窗口会取消尚未完成的候选请求。生成失败可以重试，不影响正式聊天与工作汇报。

候选只使用当前角色的近期讨论与本次要求，不套用角色口吻冒充用户，不额外读取长期偏好。候选不保存为聊天、不采集为记忆、不向工作流发送；用户明确发送后的文本才成为本窗的用户消息。

## 整理工作指令

点击聊天室顶部的 **整理指令**，选择本房间的公开原话，补充本次整理要求，再主动点击整理。只打开面板、选择原话或编辑文字不会调用模型。一次选择 1–12 条，原话合计最多 12000 字符；未完成的角色输出、其他房间及旧来源范围的内容不能作为依据。

生成使用聊天室的模型，默认跟随聊天室思考设置，单独计入「指令整理」用量。聊天室未开启思考时，先选择「开启思考并继续、保持关闭并继续」或取消；已开启时沿用，不重复询问。这是本次整理的选择，不修改全局开关。模型取得所选原话及本房间经用户核对的讨论状态，不读取人格私有偏好，也不额外获取工作会话正文。角色建议、用户决定和工程实际结果分别标明；缺少条件或有矛盾时保留待确认项，不替用户作出承诺。

草稿可以直接编辑、复制，按房间在当前页面保留。关闭面板或切换房间会取消尚未完成的整理，不影响正常聊天；保存的聊天与长期记忆不会因此改变。原话被替换、裁剪、清空或来源和讨论状态发生变化时，旧请求不能返回可用结果；尚未影响所选依据的新聊天不会无故取消整理。网络重试使用同一请求编号时，在当前运行的有限缓存内复用该次结果，不重复调用模型。

支持公开输入接口的 DSH 中，可以点击 **填入当前工作输入框**。界面会显示当前工作会话作为目标，这与聊天室固定参考来源相互独立；填入前再次核对来源，以及工作输入框的会话、版本和可编辑状态。只在原输入严格为空、无附件或引用、未被任务占用时填入，随后由用户使用 DSH 官方发送按钮提交。切换工作会话、输入内容变化或宿主不支持时保留草稿并提供复制，不覆盖已有内容，也不自动发送或执行。

需要快速取得下一步结论时，可用 **整理结论并填入**：先固定当前工作目标和空输入框版本，再完成本次思考选择、整理和依据校验。结论成功填入后，聊天室自动最小化；用户仍可在工作输入框修改，并自行发送。生成期间切换工作会话、输入文字或添加附件时，不改投新目标，也不覆盖输入；失败会保留草稿与面板，不自动最小化。

开启思考时沿用聊天室选择的强度，默认采用模型公布的默认思考档，并给予更充足的生成预算，仍受设置超时限制。若模型默认关闭但有公开的思考档，开启时使用最低非关闭档；默认未知时由提供方决定。若模型不支持思考，或能力未知、参数兼容降级后无法确认思考方式，快捷结论会保留为草稿，提示核对，不自动填入或最小化；用户仍可手动处理草稿。不保证所有模型支持同样的思考开关，思考过程不显示在结论里。

## 上下文和记忆边界

在 **插件设置 → 人格套壳 → 聊天室** 中选择模型。默认跟随转述模型，也可以单独指定提供方及模型；聊天与快捷回复共用这个选择，不改变工作助手或转述路由。

聊天室标题栏的 **设置** 提供思考开关、思考强度与原有头像外观设置。思考默认开启，强度默认「模型默认」；也可以选择当前实际模型公开的其他思考档。插件设置页的聊天室选项与这里共用同一份配置，修改只影响后续请求，已保存的关闭选择仍保留。思考可能增加等待与用量，打开设置本身只查元数据，不生成回复。

聊天室思考独立于转述的推理强度。开启时有效的自定义档优先，否则使用模型公开的默认思考档；默认是 `off` 时选最低公开非关闭档。关闭时优先选择 `off`，不能关闭的模型使用最低可用档。未公布默认或无法确认能力时采用提供方默认，不保证已开启。失效的已保存档位不会被悄悄改写，本次按默认策略兼容。明确的参数不支持错误仅在尚未输出时允许一次兼容重试。

发言模型收到当前角色卡、本房间最近的公开聊天、本条消息前序已完成的公开回应、发言者标识和本人允许读取的表达偏好，以及房间明确接入的原始工作参考。其他房间记录、其他人格的私有记忆、工具参数和思考过程不进入请求，也没有工具执行、任务分派或向工作助手发消息的能力。用户在房间提供的工作信息仍属于用户转述，不能被当作角色实际操作或独立验证的成果。

聊天采用独立提示规则，可以直接以角色身份回应；人格卡中只适用于工程汇报的 `report` 规则不会套到这里。角色设定和语气示例不作为真实历史，不虚构「已经问过姐姐」「刚跑完测试」等实际行为。

新的用户消息可以承接已有的共同话题。「其他人的看法」会把较早的完整回答作为共同进度，后位以自己的判断和理由补充，而非再复述一遍。转向闲聊时，共同转场由第一份成功保存的回复承接，其他人延续当前互动。简短括号动作是可选表达，只描述本人，不要求每位角色使用；不会把互动变成真实文件操作或长期关系。这个短期现场只保存原话位置，按房间与参考范围隔离，不增加额外模式或后台调用。

日常讨论可以一拍一拍地说：一次只接一点、短表态或回应邀请，不急着替整场聊天下结论。各人格能看到自己本次成功发言后的剩余机会，但这只是上限，既不需要用满，也不保证自动轮到下一次。暂时停下不表示话题结束。用户明确要完整说明时仍当次说清，涉及工作判断的风险与条件也不留作下次悬念；正式汇报的完整性要求不受影响。

近期完整对话之外，插件会从本房间保存的较早公开消息中，按当前话题选取最多 4 段原话，合计不超过 800 字符。每段保留作者和原消息标识，帮助接上之前的问题或建议；不自动认定它们尚未解决、已经采纳或成为约定。原话索引随房间聊天保存，不额外调用模型，不写入长期记忆；清空房间或切换参考范围后不再引用原范围片段，也不会从其他房间或人格私有记忆补入内容。

已生效偏好遵循现有的人格、会话和共享范围；本窗使用自己的会话标识，不自动继承工作会话的临时约定。首版仅复用表达偏好和互动约定，不自动把闲聊提炼成长期记忆，不把共同经历放进工程汇报。长期偏好的更正、撤销和确认仍统一在设置页完成。

关闭记忆后，不再读取保存的偏好，也不新增记忆使用记录；本窗自己的近期聊天仍作为对话上下文。清空长期记忆不会删除本窗聊天，清理聊天历史需使用浮窗中的「清空」。

## 保存、停止与重试

发送时一起保存消息、当时的成员和有序的指定对象。先点 GPT、再点大肥鱼，表示 GPT 为主要对象、大肥鱼为次要对象；不选则发给房间。顺序表示主次优先关系，不预编所有人的台词或强制全员依次出场。历史气泡保留发送时的点名，后来增减成员不会改变显示；重试旧消息也不会邀请后来才入房的人。网络重试使用同一消息编号，不会重复追加用户气泡。后发言者仅读取同一参考范围下、已经校验并保存的前序公开回应，不读取未完成的流式预览、其他人格卡或私人记忆。排队的人格不会提前显示「输入中」。

判断从用户原话保存后开始，之后按实际公共发言和可用资格动态选择下一位。每次只准备一个人格，明确关闭判断模型思考，输出预算 2048 tokens，路由准备和生成共同受插件调用超时限制。失败、截断或非法决定保留原话和已有回复，显示轻提示并提供“重试回应”；重试判断不会刷新等级或独立机会。三级且没有有效独立机会的人格不进入候选，同样的消息与资格不会反复空判断。

回复期间仍可编辑下一条草稿或更换下一次主要交谈对象，本条消息的主要名单保持固定。换来源后重试仍保留当初的点名顺序，只传入当前来源下的回复。一个人的失败不阻止后者继续，也不把失败预览当作可引用的发言。发送尚未确认时，窗口显示「正在确认…」；有可停止的回复后才显示「停止回复」，可停止当前发言与排队回应。接话判断期间显示「停止接话」。已完成正文保留，迟到的停止请求不能中断之后的新尝试。

流式通道只传本轮已解析的消息文本，不显示 JSON 包装、思考内容或工具内容。同一房间的多位发言者共用一条连接，各自按尝试编号分发，避免多人连接占满浏览器通道、阻塞停止操作。输入中的片段仅为临时预览；收到完整回复、完成原因和格式均通过校验后才保存为正式聊天。停止、失败或过时来源会清除未完成预览，不把截断文本当作完整回复。流式连接不可用时回退到快照刷新，仍保留逐条展示的停顿；打开、关闭流式连接不发起第二次模型请求。

回复要求明确正常结束，并通过短消息校验后整体保存。完整的 JSON 代码块会去掉包装；模型直接返回普通短文本时，按自然空段整理成气泡，沿用相同数量和长度限制。看起来属于 JSON 协议的内容必须完整解析，不会把损坏的 JSON 当作聊天文字兜底；思考片段也不展示。

失败保留用户消息，并在对应人格的回应下区分格式、长度、超时、模型连接等原因，不显示提供方原始错误内容。本条消息的讨论结束后，可以从失败处重试。若后面还有接话，按钮明确显示 **从这里重试**：保留前面的完整回应，重新生成该处及后续内容，避免让后者假装读过改写后的新发言。重试主要回应时丢弃旧旁听接话，主要部分完成后重新判断一次；只重试旁听接话则不重跑主要回应或判断。不重复用户气泡。原人格已离开房间时需先重新加入。

真正修改过参考范围时，会先询问是否 **按当前来源重试**；确认后只重新使用这一句用户消息和当前允许的参考，旧范围的聊天不能通过同轮接话绕回新请求。不确认就不调用模型。重启只改变连接编号时，来源范围版本保持不变，无需因为重连重新确认来源。停止、清空或修改相关记忆和人格卡后，旧请求不能写回迟到回复。

关闭窗口会移除浮窗及右下角入口，已发送的请求可以继续完成并保存；需要中止时点击「停止回复」。关闭后停止本窗读取，回复完成不向工作会话追加消息或弹出提示。再次打开读取已有记录，不自动重发。插件重启前尚未完成的轮次标为未完成，只有用户点击重试才重新生成。

「清空」要求确认，只删除当前房间的聊天记录，保留其他房间、成员、工作来源、用户头像和已保存的记忆偏好。清空或删除会推进持久化的历史代号；旧页面的后续修改核对代号，过期时刷新并保留草稿，迟到的发送、停止或清空请求不能恢复旧消息。新建同名房间也不会继承已删除房间的记录。

## 容量与当前范围

最多保留 32 个聊天室，每个房间 1–8 位人格和最近 40 条用户消息及对应回应；多人回应按同一条消息归组，保留与裁剪不会拆散一组。每次生成最多取最近 8 组同房间、同参考范围的上下文，历史合计不超过 12000 字符，按整组取用，不机械截断句子。一条用户消息最多 4000 字符；每位人格通常回复 1–3 个自然短气泡，资源上限为 6 个气泡、单个 2000 字符、合计 6000 字符。达到房间容量后明确拒绝新增，不静默删除其他记录。

聊天消息当前仅支持文字。统一调度和有限同伴交流属于用户发起的当前周期，全部安静或额度用完后等待用户，不启动脱离当前话题的常驻自主聊天。图片消息、语音、语义关联搜索和全项目摘要尚未接入。接话判断是否自然仍需实际使用验证；格式和来源检查不构成完整语义保证。

## 接口

均位于 `/persona-shell` 下，沿用 owner 认证，写入要求存储就绪。

| 接口 | 内容 |
| :--- | :--- |
| `GET /chat?room=...&session=...` | 指定房间的记录、参与者、房间目录和就绪状态；未指定房间时读取上次选择，只返回元数据，不自动生成。 |
| `POST /chat-rooms` | `create / select / update / delete`；`targetPersonaIds` 保存本次选择。名称、成员和对象变更核对 `configRevision`，与消息完成版本分别管理。 |
| `GET /chat/live?room=...&persona=...&attempt=...` | owner 认证的本轮 SSE 快照；按房间、实际发言者与尝试编号隔离，不启动模型。 |
| `GET /chat/live?room=...&batch=1` | 一个房间共用的 SSE，提供本条用户消息中各人格的独立快照；客户端按尝试编号分发，不为每位发言者另占连接。 |
| `POST /chat-context` | 带 `roomId` 的 `open / presence / attach / detach / sessions / refresh / focus / dismiss`，按房间管理来源与查看租约。 |
| `GET /chat-context?room=...&viewer=...&sequence=...` | 已选房间的查看续租与按焦点频率刷新，不隐式初始化。 |
| `POST /chat` · `send` | `roomId / personaId / recipientIds / requestId / content / revision / epoch / contextKey`，原子保存用户消息与全部接收人，固定参考范围后由统一判断逐次安排回应。对象列表可为空，表示面向房间；有选择时 `personaId` 为列表首项。 |
| `POST /chat` · `send` 的 `quote` | 可选的本房间消息位置：`roomId / generation / kind`，用户消息用 `messageId`，角色气泡用 `turnId / attemptId / index`。正文与作者由后台核对。 |
| `POST /chat` · `retry` | `roomId / personaId / id / attemptId / revision / epoch / contextKey`，新调度中只重试最后一条用户消息的一份失败回复，保留其原话依据与已完成的其他发言；跨来源范围需确认旧范围。 |
| `POST /chat` · `retry-director` | `roomId / messageId / epoch / contextKey`，显式重新判断最后一轮是否还需接话，不刷新已消费的发言或人格额度。 |
| `POST /chat` · `send / retry` 的 `clientTime` | 可选 `{timeZone, utcOffsetMinutes}`。时区和偏移经过有界校验，仅用于本轮当前时间换算；不改消息正文、幂等编号、原发送时间或房间存储。 |
| `POST /chat` · `cancel` | `roomId / personaId / id / attemptId / messageId / attempts / roundId / epoch`，按尝试编号停止回应；`roundId` 也可在判断空档停止整组，旧代号不能取消新请求。 |
| `POST /chat` · `clear` | `roomId / personaId / revision / epoch`，清空当前房间聊天，保留成员与来源。 |
| `POST /chat-discussion` | 仅设置页使用；`roomId / epoch / discussionRevision / action`。新增携带 `requestId / title / status / source`，更正与移除核对 `id / version`；终态携带用户原话 `evidence`，`undo` 撤销最近修改。后台从本房间核对原话与范围，提交后返回房间参考。 |
| `GET /chat-work-draft?room=...` | 已打开房间的可选公开原话与来源版本；不初始化聊天室或读取工作来源。 |
| `POST /chat-work-draft` | `generate` 携带 `roomId / requestId / epoch / scopeKey / discussionRevision / refs / instruction`，可选 `thinking` 仅覆盖本次，返回草稿、依据版本与思考请求状态；相同请求编号不能换思考选择复用旧结果。`validate` 只核对当前依据，不调用模型；`cancel` 以 `roomId / requestId` 停止确切请求。均不提交源工作流消息。 |
| `POST /chat/suggestions` | `personaId / roomId / revision / epoch / instruction`，基于匹配的讨论版本生成临时候选；不修改记录。 |
| `GET /avatar/:personaId?v=...` | 读取该人格当前的本地头像；不存在时返回 404，仍需 owner 认证。 |
| `POST /presets` · `avatar` | `id / requestId / expectedAvatar / avatar`，保存或移除头像；内置人格自动另存。传入的头像是规范 PNG 数据或 `null`。 |
| `GET /chat-profile` | 只读的自定义头像地址、显示方式、版本和实例标识，不包含账号资料。 |
| `POST /chat-profile` | `revision` 与 `avatar` 或 `avatarMode`，保存图片或选择 `account / custom / hidden`；不修改人格。 |
| `GET /chat-profile/avatar?v=...` | 读取用户当前头像，仍需 owner 认证。 |
| `GET /chat-references?room=...` | 只读的房间参考使用记录、当前已保存来源与暂停的旧话题。只读取现有状态，不建立来源查看租约。 |
| `POST /chat-references` | `roomId / referenceRevision / epoch / ref / excluded`，按房间独立版本暂停或恢复旧话题引用，持久化成功后生效。 |

聊天记录作为独立版本记录保存在现有插件域的 `personaChats` 键中，不进入工作会话日志或改写结果缓存。写入串行化并检查版本；完成提交还检查当前请求与人格/记忆是否仍有效。设置页的最近使用情况可按「角色聊天」筛选，只记录偏好引用和请求状态，不再复制聊天正文。

头像与预设一同保存，和语气卡 `pack` 分开；页面拿到带版本的本地图片地址，不在快照中重复携带图片数据。保存检查预期头像版本并等待持久化；同一次内置头像另存请求重复提交不会创建多个角色。修改头像期间其他预设写入会明确返回忙碌，避免覆盖。旧数据没有头像时保持无图，存储中的异常头像会忽略；删除自定义人格后，其归档聊天使用字符头像。

用户头像与可选称呼单独保存在插件域的 `chatUserProfile` 记录，更新串行化并核对版本，卸载等待已开始的写入。PNG 校验包括大小、尺寸、校验和及有限的像素解压检查，拒绝伪造或解压后超限的图片。预设保存、改名、切换和删除同样等待现有存储的写入结果再更新界面；普通写入失败会尝试恢复旧预设和选择。没有存储服务的旧宿主仍保留原有的临时人格模式，用户头像与称呼需存储就绪后才能保存。

## 讨论与工作流的边界

[整理工作指令](#整理工作指令)只生成草稿或按用户操作填入空工作输入框。角色讨论、模型建议、用户决定与正式工作指令分别保留归属；实际任务仍由 DSH 在用户发送后处理。后台主动交互、自动发送、自动执行与自动接力没有接入。
