# 配置参考

日常操作优先使用设置页。这里集中列出插件行配置、默认值和部署相关选项。

[配置项](#配置项) · [路由认证](#路由认证) · [生效顺序](#生效顺序与参数约束)

---

日常使用优先在设置页调整。插件行定义位于 [`cordis.patch.yml`](../cordis.patch.yml)，完整默认值见 [`lib/config.js`](../lib/config.js)；已保存的页面设置会在加载后恢复。

## 配置项

| 配置项 | 默认值与用途 |
| :--- | :--- |
| `enabled` | `true` · 总开关。 |
| `trigger` | `step` · 每个汇报都改写；设为 `report` 则只改每轮最终汇报。可在设置页修改默认值，或在聊天顶部单独覆盖。 |
| `includeToolSteps` | `true` · 是否改写带工具调用的中间步骤。 |
| `processToolUsage` | `false` · 允许主会话过程转述查询阶段工具计数、可确认的工作性质与轻量会话节奏；需同时开启阶段性改写，仅适用于 `trigger: step`。 |
| `memory` | `true` · 是否采集和使用结构化表达记忆；控制正文、过程补充、单次重说、静默播报与角色聊天。关闭后保留已存内容，停止采集、使用及新增使用记录。 |
| `memoryExtraction` | `false` · 是否额外调用转述模型，后台整理用户短消息为记忆候选；需同时开启记忆与总开关。 |
| `reviewHints` | `true` · 是否显示本地改写变化提示。 |
| `reviewThreshold` | `0.55` · 措辞变化提示阈值，范围 `0..1`；达到阈值才显示，关键表达变化只作解释。 |
| `progressNotices` | `false` · 是否在当前查看的主会话静默时，额外生成带 `◈` 前缀的状态播报。 |
| `progressMinutes` | `5` · 静默阈值，范围 `1..60` 的整数分钟；无新观测不重复调用。 |
| `subagentSteps` | `false` · 是否改写子代理的过程输出。 |
| `subagentReports` | `false` · 是否改写子代理的结论输出。 |
| `provider` / `model` | `''` · 改写所用模型；留空跟随当前会话。 |
| `reasoningEffort` | `''` · 默认优先关闭思考；没有关闭档位时选模型公布的最低档。非空为显式档位 ID，不支持时回到默认策略。 |
| `chatProvider` | `''` · 聊天室默认跟随转述模型；非空为独立提供方，不改变转述路由。 |
| `chatModel` | `''` · 独立聊天室模型；指定提供方但留空模型时使用该提供方默认模型。 |
| `chatThinking` | `false` · 独立的聊天室思考开关，同时用于快捷回复；支持时开启最低思考档，关闭时优先 `off`，能力未知则兼容提供方默认。 |
| `maxRewriteChars` | `6000` · 超过此长度的汇报直接跳过改写。 |
| `maxRatio` | `1.35` · 按打码文本校验长度；允许上限为原文的此倍数与原文加 200 字符中的较大值。 |
| `timeoutMs` | `45000` · 单次改写超时，单位毫秒；包含默认模型查询，超时回落原文。 |
| `keepSamples` | `2` · 随转述请求带入的历史语气样例数；样例保持打码，切换或编辑人格时清空。 |
| `maxRowsPerSession` | `240` · 每个会话保留的结果行上限。 |

## 路由认证

`allowUnauthenticatedRoutes` 默认为 `false`，没有 Connection 服务时拒绝开放 HTTP 路由。仅在明确接受未认证访问风险的特殊部署中考虑开启；它不绕过已存在的 Connection 拒绝，也不放宽 Remote 的 owner 检查。`/ping` 是不含敏感详情的公开例外。

## 生效顺序与参数约束

插件行配置先经过 `resolveConfig()` 补齐默认值；设置页可编辑的开关、阈值与模型路由，会在存储加载后恢复为已保存值。因此，修改行配置不一定覆盖设置页先前保存的选择。插件行总开关与当前会话开关仍然有效。

会话人格和转述范围的独立选择优先于全局默认；选择「跟随全局」可恢复继承。历史汇报保留生成时的角色署名。会话选择与等待接力状态持久化；存储未就绪时拒绝修改并保留页面输入。

存储恢复期间在页面修改的开关和模型路由优先于旧存储值，未修改的字段照常恢复。人格卡编辑和预设变更需等待存储恢复完成，提前操作会明确返回失败，保留页面草稿供重试。

`includeToolSteps: false` 只排除带工具调用的步骤；不带工具调用的文本仍可能是中间汇报。严格只改每轮最终汇报时使用 `trigger: report`。最终稿超长、中断或没有可改写的正文时，保留原文，不回头改写上一条阶段消息。正式改写不会额外收到后台刚调用的工具名；原汇报里本来就写出的工具仍属于正文。

类型错误或超出范围的行配置回落默认值，不自动截到最近边界。完整约束以 [`lib/config.js`](../lib/config.js) 为准：

- `maxRewriteChars`：`200..60000`；`maxRatio`：`1..4`。
- `timeoutMs`：`1000..300000`；`keepSamples`：`0..8`；`maxRowsPerSession`：`20..5000`。
- `reviewThreshold`：`0..1`；`progressMinutes`：`1..60` 的整数。
- `provider`、`model` 与 `reasoningEffort` 接受字符串并去除首尾空白。

过程运行信息需要 `trigger: step`、阶段性输出改写与 `processToolUsage` 同时开启。静默播报独立控制，默认关闭；两者的作用范围见[使用指南](./guide.md)。

角色消息区在工作页直接通过按钮打开，没有单独的设置开关。打开与查看不调用模型；只有发送、重试或明确生成快捷回复参考才请求模型。头像在设置页的预设卡片中管理，详见[角色消息区](./role-chat.md)。

## 思考模式与兼容兜底

留空 `reasoningEffort` 表示插件的自动策略，不继承工作线程的推理档位：模型公布 `off` 时明确关闭；仅提供思考档位时使用公布顺序中的最低档；未公开可选控制时不发送不受支持的参数，由提供方决定。不能关闭的模型不被标记为已经关闭思考。支持的非空自定义档位优先。

优先使用 DSH 的 `prepareCall`，在同一适配器绑定下选择档位并发送请求；旧宿主退到精确模型查询，再旧则尝试 `off`。只有尚未输出任何内容、且明确收到 `UNSUPPORTED_REASONING_EFFORT` 时，才在原请求的超时范围内去掉插件显式指定的档位，按提供方默认重试一次。普通鉴权、限流、网络、未知参数错误均不触发这次兼容重试；失败继续按原有规则显示原文。

一次逻辑请求与工具续接共用固定偏好和降级预算，已经输出文字、思考或工具内容后不重新调用。能力查询同样受超时与卸载取消约束。正文改写、人设卡提取、后台记忆整理与静默播报采用此策略；角色聊天与快捷回复使用独立的聊天室思考开关，并复用同样的能力校验和重试边界；不修改底层工作助手的模型配置。认证后的 `/diagnostics` 中，`expressionModel` 提供最近一次选择的实际档位、原因与是否降级，不保存思考内容。

档位 ID 和顺序由适配器定义，不能把各家的 `low / high` 当成通用协议。参考官方[模型能力类型](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/llm/llm/src/types.ts)与[提供方配置](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/providers.md)。
