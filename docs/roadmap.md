# 后续计划

**以下是后续功能方向。** 已具备的基础会单独说明；当前可用功能以[首页](../README.md)和[使用指南](./guide.md)为准。

以下只是方向性想法，没有排期，也不构成承诺；三点不分先后。

## 与宠物插件联动

0.5.5 已提供按工作会话查询当前人格、订阅 `persona:switched` 和自动转述事件的本地 Cordis 接口。消费方可以先查询当前状态，再订阅人格切换和会话开关变化。宠物插件可据此决定何时出场。双向互动待实际接入后评估。[接入方式](./development.md#本地插件联动)

## 人设之间的交互

当前已支持会话独立人格、转述范围与手动接力：安排下一份原始汇报交给目标人格，保留历史署名、会话偏好与私人记忆隔离。定稿汇报可以单次重说；长期记忆在设置页核对。操作与边界见[会话人格与手动接力](./conversations.md)。

当前已经具备结构化记忆的共享/人格/会话范围，以及绑定发送角色、接收角色和会话的交接记录。交接只引用可共享条目，接收幂等，并在读取时重新检查范围；角色私有互动不会自动成为另一角色的经历。接口与当前边界见[记忆与接力基础](./memory.md#为多个人设接力预留的规则)。

0.5.5 的手动接力支持附交接卡。接棒人格只在首份转述读取说明及当时仍可共享的条目，首份转述结算或接力取消后关闭卡片。清空记忆会移除交接卡，已经安排的接力仍可正常转述。角色行为参数仍待设计。

角色消息区已支持多房间：同房成员共用一条聊天记录，草稿和参考来源按房间分开。用户可以向整个房间说话，也可有序选择多位对象；统一调度结合最新现场、独立冷却与剩余机会安排接话。快捷回复点选后只填入输入框。正式汇报仍依照工作原文改写，详见[角色消息区](./role-chat.md)。

多房间已补本地名称与成员搜索、最近访问排序、草稿与回复状态提示，以及按房间恢复阅读锚点和输入选区。profile 命名空间可用时，未发送草稿仅在浏览器本地跨客户端重启恢复；存储失败回退页内状态。较长等待只展示实际阶段、本轮用时与已解析模型，不新增后台判断调用。

已加入统一调度中的工作参考筛选：结合用户原话、最新公共聊天与已授权来源元数据，按需为下一位准备上下文。纯闲聊不主动带入工作片段，判断失败也不全量注入资料。选择依据只在设置页核对，不变更房间来源、点名对象或长期记忆；模糊意图的理解与实际回复是否自然，仍需分开验证。

已加入按本轮发言顺序分配的临时职责，以及设置页中带原话依据的房间讨论状态。用户可整理、更正和撤销候选方案与决定，状态按房间和参考范围隔离；没有自动提炼决定或后台整理调用。后续可在这套可核对的基础上完善讨论连续性，而不将人格表达、用户决定与工程实际结果混为一谈。

已加入「讨论想法 → 选择原话 → 整理可编辑工作指令」的主动流程，支持复制；宿主提供公开输入接口时，可在核对目标和依据后填入当前工作输入框，再由用户使用官方发送按钮提交。不会自动覆盖原有输入、提交任务或执行指令。后续可继续完善讨论连续性与草稿核对；后台主动交互、自动任务分派与自动接力不属于当前功能。

工作汇报尚未接入自动主持权切换或第二位人格校对。下一步应先用真实汇报验证手动接力的归属、成本和反馈，再决定是否引入独立校对；角色相互改写的文本不能成为新的事实来源。

0.5.5 的聊天室已接入公开资料调查、深度推演和工作参考整理三种固定模板。每个模板限定可读资料、工具和调用预算。工作汇报中的独立校对仍待评估。详见[聊天室辅助任务](./role-chat.md)。

## 细化实验性小肥鱼的适配

「小肥鱼（实验性）」已通过明确的发言关系区分转述者与工作者，主助手默认称「姐姐」，子代理采用卡片中的子代理称呼。0.5.5 的编辑器可启用严格转述并补充自称，引语外使用第一人称或卡片声明的自称时会提示核对。仍需用真实汇报继续验证：

- 「姐姐」在不同来源（主助手、子代理、其他模型）下是否始终合适，遇到不适用的情况如何降级；
- 原文本身使用第一人称或转述他人时，怎样避免把「姐姐说」套成新的歧义；
- 长汇报、混合语言、命令与报错密集的场景下，转述关系是否还清楚，以及示例句和禁区是否需要再收窄。
