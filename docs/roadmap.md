# 后续计划

**以下是后续功能方向。** 已具备的基础会单独说明；当前可用功能以[首页](../README.md)和[使用指南](./guide.md)为准。

以下只是方向性想法，没有排期，也不构成承诺；三点不分先后。

## 与宠物插件联动

先把本插件和宠物插件之间的边界做成松耦合：本插件只暴露稳定的轻量事件和查询接口（例如一条汇报完成人格改写、改写失败回落、会话开关切换、当前生效的人格预设），宠物插件按自己的节奏订阅并决定表情、动作或台词；本插件不反向依赖宠物插件，未安装宠物插件时行为完全不变。等这套接口稳定后，再讨论更深的双向互动。

## 人设之间的交互

当前已支持会话独立人格、转述范围与手动接力：安排下一份原始汇报交给目标人格，保留历史署名、会话偏好与私人记忆隔离。定稿汇报可以单次重说；长期记忆在设置页核对。操作与边界见[会话人格与手动接力](./conversations.md)。

当前已经具备结构化记忆的共享/人格/会话范围，以及绑定发送角色、接收角色和会话的交接记录。交接只引用可共享条目，接收幂等，并在读取时重新检查范围；角色私有互动不会自动成为另一角色的经历。接口与当前边界见[记忆与接力基础](./memory.md#为多个人设接力预留的规则)。

记忆第一批改进已经加入原话依据、目标版本校验、更正、撤销与设置页确认。经过授权的交接卡与行为参数仍需后续设计；模型的自我解释和用户没有反对，都不作为人格自动成长的证据。

角色消息区已支持多房间：同房成员共用一条聊天记录，草稿和参考来源按房间分开。用户发言时可点选一至两位主讲，其余成员按需接话。快捷回复点选后只填入输入框。正式汇报仍依照工作原文改写，详见[角色消息区](./role-chat.md)。

后续优先考虑「讨论想法 → 整理提示词草稿 → 用户确认 → 以用户消息提交源工作流」的连续体验。消息区可以协助细化需求，但转交前必须让用户看到可编辑的完整指令、目标会话及必要上下文，避免把闲聊直接当成工作授权。首版没有接入提示词转交或自动执行；也不承担后台主动交互或自动接力。

工作汇报尚未接入自动主持权切换或第二位人格校对。下一步应先用真实汇报验证手动接力的归属、成本和反馈，再决定是否引入独立校对；角色相互改写的文本不能成为新的事实来源。

## 细化实验性小肥鱼的适配

「小肥鱼（实验性）」已通过明确的发言关系区分转述者与工作者，主助手默认称「姐姐」，子代理采用卡片中的子代理称呼；编辑器可调整转述模式与原助手称呼。仍需用真实汇报继续验证：

- 「姐姐」在不同来源（主助手、子代理、其他模型）下是否始终合适，遇到不适用的情况如何降级；
- 小肥鱼自己的「我」可以出现到什么程度，是否需要提供一个完全不出现第一人称的严格模式；
- 原文本身使用第一人称或转述他人时，怎样避免把「姐姐说」套成新的歧义；
- 长汇报、混合语言、命令与报错密集的场景下，转述关系是否还清楚，以及示例句和禁区是否需要再收窄。
